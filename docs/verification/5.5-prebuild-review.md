# Pre-build review: 5.5

Reviewer (pre-build), base `8134305`, working-tree story and architecture. Verdict: **changes**. All 15 points are `[story]`: none contradicts a PRD requirement or an architecture decision. The 2026-10-30 one-fixed-hash decision holds, but only for the page at exactly `/scalar/`.

**Checked in the installed versions.** Scalar.AspNetCore 2.18.3 (Directory.Packages.props) with Microsoft.AspNetCore.OpenApi 10.0.14. I rendered the page in a scratch app outside the repo (`/private/tmp/claude-501/-Users-njabulomnisi-Projects-Dojo-DisputeDesk/77858989-3f5b-4d04-8184-f4d922dc16d1/scratchpad/scalar/app`) and read the `scalar.js` and `scalar.aspnetcore.js` embedded in the DLL. What it showed:

- **Scripts.** The served HTML has two external scripts (`scalar.js`, `scalar.aspnetcore.js`) and exactly one inline `<script type="module">`. That script contains `initialize('%2Fscalar%2F', false, {config JSON}, '')`.
  - The first argument is the URL-encoded request path. `/scalar/`, `/scalar/v1` and `/SCALAR/` each give a different hash. The query string does not change it, and `/scalar` gets a 302 to `scalar/`.
- **Styles.** The HTML has no inline `<style>` element and no `style=` attribute. `scalar.js` adds styles at runtime: `createElement('style')` for Tailwind (nonce taken from `meta[property=csp-nonce]`) and for a CodeMirror style module, plus `setAttribute('style', …)`.
- **Config JSON with the story's options:** `{"withDefaultFonts":false,"favicon":"favicon.svg","_integration":"dotnet","sources":[{"title":"v1","url":"openapi/v1.json"}],"telemetry":false}`.
- **Persistent auth.** It defaults to off, and the bundle writes auth to localStorage only when `persistAuth` is true (`o()&&e.type==='auth'`). So criterion 2's claim holds for 2.18.3.
- **Agent Scalar (AI chat).** Enabled unless `agent.disabled`. The bundle's rule is `agent?.disabled ? false : isLocalhost(location) ? true : !!agent.key`, so it is on at `localhost:8080`. Developer tools default to `'localhost'` too.
- **Eval.** The bundle has no `eval` or `new Function`. It has one `Function('')` capability probe inside try/catch (zod's jitless check).
- **HEAD.** `/scalar/`, `/scalar/scalar.js` and `/openapi/v1.json` all answer HEAD with 405, because they are mapped as GET only.
- **Forwarded headers.** No ForwardedHeaders code exists in `backend/src` yet (AD-23's Api trust is not built).

## Resolution

Sofia, 2026-10-30. Story 5.5 is refined to six criteria; decisions 1 (only the `bearer` scheme) and 2 (`style-src 'self' 'unsafe-inline'` on the Scalar locations only) were settled by the human on 2026-10-30.

- Hash valid only at `/scalar/`: criterion 6 requests exactly `/scalar/`; criterion 4 forwards the path unchanged (`proxy_pass http://api;`, no rewrite, no `X-Forwarded-Prefix`); a Boundaries line says other page paths render blank and fail closed. AD-26 now reads "the page at `/scalar/`".
- Styles: criterion 5 fixes `style-src 'self' 'unsafe-inline'` (decision 2); the style-hash branch and the builder's browser step are cut.
- Agent Scalar, MCP and developer tools: criterion 2 adds `DisableAgent()`, `DisableMcp()` and `HideDeveloperTools()` (all present in Scalar.AspNetCore 2.18.3's XML docs).
- Supervisor check's "no CSP violation": reworded; the supervisor records every violation, the only expected one being the refused `'unsafe-eval'` from the zod probe.
- Smoke loop with HEAD: criterion 5 reads `/scalar/` with GET (`curl -fsS -D - -o /dev/null`).
- "Either scheme" and the `scopes` map: dropped by decision 1; criterion 3 asserts exactly `security: [{"bearer": []}]`.
- `tokenUrl` bounds and the Zitadel endpoint source: dropped by decision 1.
- Options class name and switch bounds: criterion 1 names `ApiReferenceOptions` (section `Scalar`, `ValidateOnStart`) and tests `true`, `TRUE`, absent (off) and `yes` (fails start); the Options pattern is cited.
- Testing the options: criterion 2's test parses the `initialize` configuration; a supervisor check covers `localStorage`.
- One inline script and one template hash: criterion 6; Touches names the repo-root lookup copied from `SourceRoots`.
- Launch profile: criterion 1 and Touches add `Properties/launchSettings.json`.
- `servers` in AWS: a Boundaries line ties it to AD-23's forwarded headers (story 7.4).
- Copied header values: criterion 5's smoke check compares each non-CSP value with `/`'s.
- References and the `tickets.toml` entry: Scalar's ASP.NET Core integration, nginx `add_header` and the Options pattern added; the entry's description, verify, touches and all four supervisor checks synced.
- `StandInSettings` comment: dropped by decision 1 (no stand-in issuer; `BuildTimeOpenApi.cs` is not touched). The `RelativePath` leading slash: a Notes line for the builder.
