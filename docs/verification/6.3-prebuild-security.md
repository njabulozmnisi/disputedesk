# Pre-build security read: 6.3

Security (pre-build), base `ef80148`, read against 6.1's uncommitted `Program.cs`, `docker-compose.yml`, `infra/nginx/templates/nginx.conf.template` and the 2026-10-30 human decisions. No high, no `[decision]`. Already covered: the Api publishes no host port. The gateway overwrites `X-Forwarded-For` with `$remote_addr` and sets `Host` and `X-Forwarded-Host` itself. Criterion 1 covers sliding windows, the chained limiters' spent IP permit and `Retry-After`. The two carried 2.8 log items are in the Notes.

| # | Sev | Finding |
|---|---|---|
| S1 | medium | [story] Criterion 3 and AD-23 contradict decision (1). They say `KnownProxies` holds only the gateway, `KnownIPNetworks` is empty, and the gateway is resolved at start-up. In the installed .NET 10.0.14, `ForwardedHeadersOptions.KnownNetworks` is `[Obsolete]` (ASPDEPR005, checked in the reference pack's docs and assembly), and its replacement is `KnownIPNetworks` (`System.Net.IPNetwork`). Rewrite the criterion: clear both loopback defaults, put the configured range in `KnownIPNetworks`, leave `KnownProxies` empty, `ForwardLimit` 1, For/Proto/Host, with `UseForwardedHeaders` first in the pipeline (Microsoft Learn, *Configure ASP.NET Core to work with proxy servers*). Amend AD-23. (ASVS V4.1.3) |
| S2 | medium | [story] The range has to match the network. Pin the Compose default network's subnet (`networks.default.ipam.config`) and pass the same range as a named configuration key. Validate it at start with `IPNetwork.TryParse` and `ValidateOnStart`, and add the key to AD-26's list. A mismatch fails silently: every client becomes the gateway's address, one IP partition, and 20 requests in 15 minutes lock linking out for everyone. State that every container on that network is trusted. Supervisor Docker check: send `X-Forwarded-For: 203.0.113.9` through the gateway and confirm the audited `ClientIp` is the host's client address, neither that value nor the gateway's. (ASVS V4.1.3) |
| S3 | medium | [story] "Only the first rejection per partition per window is audited" names no mechanism, and the built-in limiter exposes none. A home-grown dictionary keyed on client IPs grows without bound (an attacker can rotate IPv6 /64 prefixes). Name the documented form: `IMemoryCache` with `SizeLimit`, one entry per limiter and partition key, expiring after the window length from that first rejection (Microsoft Learn, *Cache in-memory in ASP.NET Core*). A rare double audit under a race is acceptable. (ASVS V2.4.1, V16.3) |
| S4 | low | [story] The global limiter picks linking requests from the matched endpoint's metadata on the linking group, not from a path string. `UseRateLimiter` comes after routing and `UseAuthentication`, so `sub` is available (Microsoft Learn, *Rate limiting middleware*). A request with no `sub` uses no login limiter, since authorization answers 401. `QueueLimit` is 0, so a rejected request holds nothing and calls no handler, database or job. Test that an upper-case path to the start route is limited. |
| S5 | low | [story] Both limiters answer with the same `rate-limited` ProblemDetails: `type`, `title`, `status` and `traceId` only, never the partition key (IP or `sub`) or the counts. `Retry-After` is whole seconds rounded up (RFC 9110 §10.2.3). The test asserts the body's fields. (ASVS V16.5.1) |
| S6 | low | [story] "`AllowedHosts` holds the public app host" can mean two settings: `ForwardedHeadersOptions.AllowedHosts` (`X-Forwarded-Host` values) or host filtering. Name which. If host filtering is set, the in-container health probe (`Host: 127.0.0.1:8080`) must still pass without falling back to `*`. |
