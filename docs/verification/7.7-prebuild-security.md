# 7.7 pre-build security (status: findings, all low)

The operator UPDATE is safe as written:
- It targets one row by `Id` and `Status = 'Failed'`.
- It runs in an explicit transaction and commits only on `UPDATE 1`.
- `Payload` is untouched; a row is never set `Sent` and never deleted.
- The release is proved by per-dispute order on the topic.

- **S7.7-1 low [story] How the operator runs it.**
  - Run it in an interactive session with no password on the command line: `docker compose exec postgres psql -U disputedesk -d disputedesk`, then `\set ON_ERROR_STOP on`.
  - Pass the event ID as a psql variable: `\set event_id '<GUID>'`, then `WHERE "Id" = :'event_id'::uuid`. psql quotes the value, and the cast rejects a malformed ID.
  - Standard: psql variable interpolation; OWASP Query Parameterization Cheat Sheet.
  - Builder must test: `7.7-run.md` shows the exact session.

- **S7.7-2 low [decision] Runs as the owner role, and leaves no audit record.**
  - The release runs as `disputedesk`, the app's owner role, which has full DML. It also writes no audit record (ASVS 5.0 V16.3).
  - Accept this for the local-only runbook. `docs/production-path.md` gets a dedicated operator role with column-level `GRANT UPDATE ("Status","Attempts","NextAttemptAtUtc")` and an audited release.
  - AD-22 names the role, so this is a decision.

- **S7.7-3 low [story] Scope.** The runbook says its procedures are for the local stack only. For AWS, where RDS is private, it links 7.5's README.

- **S7.7-4 low [story] No secrets in the run record.**
  - `7.7-run.md` holds no bearer token, client secret, PAT or OTP. It records status codes and problem types only.
  - `curl -H "Authorization: Bearer $(scripts/operations-token.sh)"` puts the token in curl's argv, visible in `ps`. That is acceptable on a single-user dev machine; say so.
  - The README notes that the fixture passwords are also live in the AWS demo (S7.4-11).
  - Builder must test: `scripts/secret-scan.sh` passes on the worktree, untracked files included, and the run record contains no `eyJ` (a JWT prefix).

## Resolution

Sofia, 2026-10-30, with the human's decision of 2026-10-30 on the `[decision]` point. The story keeps 6 criteria.

- S7.7-1: an interactive `docker compose exec postgres psql` session with `ON_ERROR_STOP` and the event ID as `:'event_id'::uuid` (criterion 4, step 3).
- S7.7-2 [decision], human: accepted and documented. The runbook says the release runs as the owner role with no audit record, for the local stack; story 7.6's Notes carry the production-path entry (a dedicated operator role with column-level grants and an audited release).
- S7.7-3: the runbook says it is local-only and links `infra/terraform/README.md` for AWS (criterion 4).
- S7.7-4: the run record holds no secret (Inputs); the README notes the token in curl's argv and that the fixture logins are live on the AWS demo (Inputs; criterion 1); `scripts/secret-scan.sh` passes and the record contains no `eyJ` (Verify).
