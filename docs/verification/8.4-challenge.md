## Pre-mortem

- [story] The privacy test passes while a new metric leaks a private label. `StoredEventPrivacyTests` currently observes every instrument on the Api’s meter factory, but `TelemetryCapture` exports only configured meters and can collect measurements from parallel tests. Specify how the replacement proves coverage of newly added instruments and attributes measurements to this Api; a nonempty export alone does neither.
- [story] A duplicate core-banking call escapes the absence tests. `HoldNext()` holds only the next call; later calls pass through, and a call made *after* the held call is released cannot be excluded by an assertion made while it is held.

## Simplest design

- [story] Use `MetricCollector<T>` for named instruments, its `Instrument` property for the existing histogram metadata assertions, `FakeLogCollector` for captured logs, and `FakeTimeProvider` for clocks. Keep the OpenTelemetry exporter only where export itself or all exported labels are under test. Avoid a new recorder abstraction around these tools.
- [story] Create disputes through `Dispute.Raise` and the required aggregate actions, then save once. Retain narrowly named direct-row fixtures for deliberately malformed or unknown stored events rather than forcing those tests through a status-only helper.

## Assumptions

- [story] A single `DisputeIn(status)` can replace all `AppendAsync` uses. That is doubtful: current tests construct particular actors, outcomes, event times and concurrent appends; `NotFoundResponsesTests` intentionally constructs an impossible every-type stream. State which cases the helper replaces and which remain deliberate exceptions.
- [story] One `Eventually.UntilAsync(condition, timeout)` preserves the Worker’s polling behavior. `OutboxFixture.WaitUntilAsync` also advances a `FakeTimeProvider` on each attempt; the proposed signature has no clock input or stated replacement for that behavior.

## Standards

- [story] The named metric, logging and clock fakes are documented framework test tools: [MetricCollector<T>](https://learn.microsoft.com/dotnet/api/microsoft.extensions.diagnostics.metrics.testing.metriccollector-1?view=net-10.0-pp), [FakeLogger](https://learn.microsoft.com/dotnet/api/microsoft.extensions.logging.testing.fakelogger?view=net-10.0-pp), and [FakeTimeProvider](https://learn.microsoft.com/dotnet/api/microsoft.extensions.time.testing.faketimeprovider?view=net-10.0-pp). No nonstandard production mechanism is needed. The proposed `Eventually` helper is test-local coordination, not a framework standard; keep it limited to the genuinely shared polling behavior.
