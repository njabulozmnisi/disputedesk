# Security: 2.2

- Reviewer: `security` agent (Claude Opus 5.5), read-only. No high or medium findings; nothing escalated.
- Scanners: gitleaks (no leaks), `dotnet list package --vulnerable --include-transitive` (none), Semgrep `p/csharp`, `p/secrets`, `p/security-audit` (0 results; partial coverage of four files with primary constructors), Trivy (nothing applicable).
- New packages: `Microsoft.AspNetCore.Authentication.OpenIdConnect` and `Microsoft.AspNetCore.DataProtection.EntityFrameworkCore`, both Microsoft, pinned at 10.0.13 with the rest of the 10.0.x set.

## What holds

Code flow with PKCE, nonce and state; `email_verified` must be `"true"`; a new 32-byte session key on every sign-in, stored only as its SHA-256; the ticket protected by Data Protection; idle and absolute limits enforced on read; logout deletes the row before the end-session redirect and the old cookie gets 401; HttpOnly, SameSite=Strict cookies with `__Host-` names and Secure in AWS; `returnUrl` limited to local paths; antiforgery bound to the login; problem bodies carry only a trace ID; no token is logged.

## Findings

| # | Severity | Finding | Resolution |
|---|---|---|---|
| L1 | Low | OIDC callback and sign-out return URLs come from the request; behind CloudFront TLS they would be `http://` | The forwarded-headers story must land before any HTTPS deployment |
| L2 | Low | Data Protection keys are stored unencrypted in Postgres; database read access can unprotect tickets, which now hold the ID token | Recorded for `docs/production-path.md` (KMS-wrapped key ring) |
| L3 | Low | Logout left the antiforgery cookie | Fixed: logout deletes it |
| L4 | Low | Handler sent `client_secret_post`, app provisioned as basic | Fixed: provisioned as POST |
| L5 | Low | BFF app kept the unneeded refresh-token grant | Fixed: code grant only |
| L6 | Low | The Api mounts the operations-tools client secret, which only `smoke.sh` needs | Open: later cleanup |
| L7 | Low | `zitadel-clients.json` overrode environment variables | Fixed |
| L8 | Low | `BFF_DEVELOPMENT_MODE` not validated | Fixed: only `true` or `false` |
| L9 | Low | The sign-in failure log can carry the callback's `error_description` | Accepted: structured logging |
| I1 | Info | Antiforgery is added per endpoint | Apply it at the customer and linking group level when those groups exist |
| I2 | Info | An anonymous cross-site logout POST can end the Zitadel session | Accepted: a nuisance only; the DisputeDesk session is untouched |
| I3 | Info | AD-24's external port and TLS mode are not yet configurable | Left to the AWS compose file |

## Decision after review

QA showed that without `id_token_hint` the Zitadel session survived sign-out until a click. The ID token is now kept in the protected ticket and sent as the hint (AD-7 amended). The token crosses the browser once, in the end-session redirect.
