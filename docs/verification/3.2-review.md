## Lane experiment (human decision, 2026-10-28)

The 3.2 builder was dispatched as a fourth lane, over the two-lane cap and under memory pressure 2, as an experiment. Sampled every 30 s for 30 minutes (57 samples): pressure 1 in 13, 2 in 44, 4 never; peak swap 13.9 GB; reclaimable memory never under 2.4 GB. No OOM, killed process or lock timeout. The one cost was contention: the `stack` lock covers a single command, so another lane took it between the builder's `compose up` and its smoke requests and restarted the shared stack; the builder reran the whole smoke check as one locked command. Builder wall time 30 minutes, about 367k tokens.

### Postmortem: second fix round (trigger)

- What: fix round 2 exists only for S4, a gitleaks `generic-api-key` hit on an example UUID in `backend/http/disputes.http`, present since round 0. Pre-commit and CI gitleaks would refuse the commit.
- Why it escaped: the builder ran no gitleaks check; security's round-0 scan covered `backend/src` only, so a file outside `src` was never scanned until the delta re-run piped the whole uncommitted diff through `gitleaks stdin`.
- Fix proposal (for the human, one batch): a deterministic check, not a sentence. Add to the build-story finish checks a gitleaks scan over the whole uncommitted diff, tracked and untracked (the same input the pre-commit hook will see), and make the security stage use the same command. Until then, one "Known pitfalls" line in build-story: example UUIDs and tokens in docs, `.http` files and tests trip `generic-api-key`; use low-entropy placeholders.
