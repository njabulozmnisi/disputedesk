## 1. Pre-mortem

- [story] **The skip link fails its keyboard test.** `usePageHeading` focuses the `<h1>` on navigation; Tab from that heading does not return to a skip link placed before the header. Criterion 7 conflicts with the existing focus behavior in `EXPERIENCE.md`.
- [story] **Withdrawal appears successful but the screen stays stale.** Criterion 3 invalidates dispute queries but omits the transactions query required by `EXPERIENCE.md`. The specified “already withdrawn” 409 also needs the same refresh and success announcement.
- [story] **Load more focuses the wrong row.** The API pages disputes newest-first, but the screen redistributes each page into Open and Closed. The first newly loaded item need not appear at the end of either rendered group.

## 2. Simplest design

- [story] Use the generated infinite-query hook and cursor, group loaded rows by `customerStatus`, and retain API order within each group. Use one generated detail query and withdraw mutation, the existing status mapping, native `<ol>`/`<time>`, and the installed `AlertDialog`. Identify the first new row by dispute ID rather than rendered index; invalidate detail, disputes, and transactions after either successful response or the specified 409.
- [story] Keep unrelated `FieldSet` removal, raise-screen styling, and exhaustiveness cleanup out of this story unless a touched component actually requires them. The Build facts currently request those changes without tying them to a criterion.

## 3. Assumptions

- [story] **The required API hooks will exist before the frontend build.** The current generated client has a detail hook but no disputes-list or withdraw hook; stories 3.9 and 3.4 supply those contracts. Make their merged, regenerated contract an explicit build precondition.
- [story] **A 409 carrying `withdrawn` means this withdrawal can be presented as complete.** FR-18 explicitly permits that interpretation, including when another request completed it. The screen should fetch the resulting timeline rather than imply its own note was saved.
- [story] **The signed-out return path is safe.** AD-31 requires no dispute ID in `returnUrl`, but `createQueryClient` currently uses `router.state.location.href`. Specify `/disputes` as the detail-screen fallback and test the resulting sign-in URL.

## 4. Standards

- [story] Do not add a keyboard interceptor to force Tab back to a skip link. Use a native first-in-document skip link targeting a focusable `<main>` ([WCAG technique G1](https://www.w3.org/WAI/WCAG22/Techniques/general/G1)); explicitly reconcile that behavior with the existing route-change `<h1>` focus rule. No other invented mechanism is needed: the specified dialog follows the [WAI-ARIA alert dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/), and cache refresh should use [TanStack Query invalidation](https://tanstack.com/query/latest/docs/framework/react/guides/query-invalidation).

## 5. Gaps

- [story] Criterion 1 omits the transaction summary required on every history row by FR-16. Specify the displayed snapshot fields, Open/Closed status membership, and a test where newly fetched rows land in both groups.
- [story] Criterion 3 does not specify the withdrawal note’s **post-trim 500 UTF-16-code-unit** bound from story 3.4, empty-note handling, inline 400 errors, or the pending/network-error state. Add boundary and failure tests; do not silently truncate pasted text.
- [story] Criterion 5 should distinguish an unknown GUID (404) from a malformed route ID (the detail endpoint documents 400), and test that a linked customer sees the identical not-found screen for an unknown valid ID and an unknown route.
- [story] Criterion 7 is not testable alongside the current `<h1>` focus rule as written. Decide which element receives focus after client-side navigation, state the expected first Tab target for both initial load and route change, and test those separately.

## Resolution

2026-10-30, Sofia (refine). Every point was `[story]`. The story split: `story-3.7-disputes-history-screen-and-the-shells-skip-link.md` (history) and `story-3.12-dispute-detail-timeline-and-withdraw-screen.md` (detail and withdraw).

- Skip link against the `h1` focus rule: a first-in-document skip link moving focus to `main` by script (G1); route changes still focus the `h1`; the two cases tested separately (3.7 criterion 6; EXPERIENCE.md amended).
- Stale screen after withdraw: detail, disputes and transactions queries invalidated after 200 and after the `withdrawn` 409 (3.12 criterion 6).
- Load more focus: by `disputeId`, with a test where a page adds rows to both sections (3.7 criterion 3).
- Simplest design: generated hooks, API order within groups, native `<ol>` and `<time>`, the installed `AlertDialog` (both stories).
- Unrelated cleanups: moved to the epic's Notes as a Small-tier follow-up.
- Hooks must exist: 3.7 waits on 3.9 and 3.12 on 3.4 (`after`).
- 409 `withdrawn`: counts as success and refetches the detail rather than implying the note was saved (3.12 criterion 6).
- `returnUrl`: `/disputes` after a 401 on any `/disputes/<…>` path (3.12 criterion 7).
- Transaction summary on history rows and Open/Closed membership: 3.7 criteria 1 and 3.
- Note bounds, empty note, inline 400, pending and network states: 3.12 criteria 5 and 6.
- Malformed ID versus 404: a GUID-only `params.parse` throws `notFound()` before any request; one not-found screen for every case (3.12 criterion 1).
