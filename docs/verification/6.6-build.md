# 6.6 build

Story 6.6 is built and left uncommitted in the worktree. All 1203 backend tests pass, and the smoke check through the gateway showed both criteria holding on the running stack.

**What changed**
- **Forwarded headers:** `Security/ForwardedHeadersTrust.cs` and `Security/ForwardedHeadersTrustOptions.cs` configure ASP.NET Core's built-in Forwarded Headers middleware. It processes For, Proto and Host, and the loopback defaults and `KnownProxies` are cleared. `KnownIPNetworks` holds only `ForwardedHeaders:TrustedNetwork`, `ForwardLimit` is 1, and `AllowedHosts` holds only `ForwardedHeaders:AllowedHosts`.
- **Start-up validation:** both keys use `ValidateOnStart`. A missing or unparsable range, or an empty host, stops the Api with an error naming the key.
- **Pipeline:** `Program.cs` calls `app.UseForwardedHeaders()` first.
- **Build-time OpenAPI:** `BuildTimeOpenApi.cs` gets stand-in values for the two keys so the build-time document still generates. `openapi.json` is unchanged.
- **Compose:** `docker-compose.yml` pins the default network to `10.201.89.0/24` and passes the same range, plus `AllowedHosts: localhost`, to the api.
- **Gateway:** the identity origin's `server` now logs with a `log_format identity`. It records `$request_method $uri $server_protocol` and has no `$request`, `$request_uri`, `$args` or `$http_referer`.

**Smoke check** (project `disputedesk-smoke66`, OTLP ports moved, behind the `stack` lock, removed afterwards)
- The stack came up healthy, so the in-container health check still passes host filtering. The network is `10.201.89.0/24`; the gateway container is `10.201.89.10`.
- The login's `redirect_uri` is `http://localhost:8080/api/signin-oidc`.
- Customer C's start with forged `X-Forwarded-For: 203.0.113.9` and `X-Forwarded-Host: attacker.example` returned 202. Both audit rows have ClientIp `10.201.89.1`, the host's address as nginx saw it. That is neither the forged value nor the gateway's.
- Customer A's sign-out logged `"GET /oidc/v1/end_session HTTP/1.1" 302`, with no `id_token_hint`, even though the end-session URL carried it.

**Things you should know**
- **The existing local network needs recreating once.** The `disputedesk_default` network on the shared daemon is still `192.168.48.0/20`. The next `docker compose up` of the default project will probably need one `docker compose down` (without `-v`) first.
- **Parallel stacks can't share the subnet.** Because the subnet is fixed, two Compose projects of this repo can't have networks at the same time. That affects throwaway QA or supervisor stacks. Making it overridable like the ports is an option; I didn't add it because the story says "pins".
- **Authorization codes in the app-origin log (open item, outside this story).** The app origin still uses nginx's default combined log. `dev-login.sh`'s GET callback puts `/api/signin-oidc?code=…` (JWT-shaped) in that log. Real browsers use `form_post`, so they don't.
- **One test case dropped.** I removed a `10.201.89.5/24` case: .NET 10.0.14's `IPNetwork.TryParse` accepts it, contrary to its docs. The story names `TryParse` as the check, so I didn't add a custom parser. The resulting network still covers the same /24.
