## Pre-mortem

- [story] The history ships without an `outcome`: FR-16 requires it for resolved disputes, but neither the existing `DisputeResponse` nor the committed OpenAPI schema has the field. The story’s “no shape changes” boundary conflicts with its own list criterion.
- [story] Detail returns 500 on a future stored event: `StoredEventRow.ToStoredEvent()` throws for an unknown `EventType`, and the existing replay loader deserialises every row. The customer read needs to skip unknown rows **before** calling that method, while replay must continue to throw.
- [story] Ownership coverage appears complete while a new route is unprotected: a test that selects only endpoints already requiring `Linked` cannot discover one missing that policy.

## Simplest design

- [story] Query the ownership-filtered `Disputes` read model for a `limit + 1` keyset page ordered by `(CreatedAtUtc, Id)` descending. Map small list rows, including nullable `outcome`; use the existing `CustomerView` for status and the detail timeline. Detail loads its owned read-model row and its stored-event rows in `Version` order, filters unknown event names before deserialisation, then applies the existing type allowlist. No replay, new timeline table, generic event framework, or second customer mapper is needed.
- [story] Use the existing group’s `Linked` policy and ProblemDetails path. Make the route and the raise `Location` share one constant; test the actual `Location` with a GET.

## Assumptions

- [story] Showing timeline `action: "escalate"` is acceptable alongside `customerStatus: "underReviewPrioritised"`. The existing `TimelineEntryResponse` and allowlist test emit `escalate`, but the story explicitly leaves the customer-facing meaning open. Settle the expected wire value before building.
- [story] Stored snapshot timestamps may have finer precision than PostgreSQL retains. `RaiseDisputeHandler.ToSnapshot()` copies the core-banking instant, while the story notes that the 201 and subsequent GET can differ. Decide where precision is normalised and test equality.
- [story] The backend alone can satisfy FR-17’s rejected-outcome guidance. The PRD requires customer-facing complaint guidance, but this backend-only story has no criterion or identified later frontend owner for that copy.

## Standards

- [decision] Exact-case enum reading is **not** what the architecture’s named `JsonStringEnumConverter` provides: Microsoft documents case-insensitive reads. If exact names are required, amend AD-5 to permit a focused `System.Text.Json` custom converter and test it through HTTP, not just direct deserialisation. [Microsoft: enum converter](https://learn.microsoft.com/dotnet/api/system.text.json.serialization.jsonstringenumconverter).
- [story] A `Z` suffix for `DateTimeOffset` needs an explicit serialization approach; the current serializer emits `+00:00`. Use [System.Text.Json’s documented custom-converter extension point](https://learn.microsoft.com/dotnet/standard/datetime/system-text-json-support#custom-support-for-datetime-and-datetimeoffset), or seek a decision to accept `+00:00`. Do not silently rewrite persisted event or idempotent-response JSON.
- [story] Keep ownership in the existing [EF Core global query filter](https://learn.microsoft.com/ef/core/querying/filters), paging as [keyset pagination](https://learn.microsoft.com/ef/core/querying/pagination#keyset-pagination), and `limit` validation in [ASP.NET Core’s built-in validation](https://learn.microsoft.com/aspnet/core/fundamentals/validation?view=aspnetcore-10.0); no new mechanism is warranted.

## Gaps

- [story] Specify the list-row contract, including `outcome`, and whether detail also exposes the resolved outcome. Update the “no shape changes” boundary accordingly.
- [story] Enumerate expected customer routes independently in the `EndpointDataSource` test, then assert each has `Linked`; include newly added routes so a missing policy fails.
- [story] Bound `cursor` length and decoded shape; test malformed-but-base64url input, ties on `CreatedAtUtc`, page boundaries, and a final null cursor. State the expected response for a malformed `disputeId`.
- [story] Criterion 4 asks for identical 404 bodies across detail and raise, but raise looks up a **transaction**, while detail looks up a **dispute**. Specify one safe problem detail for both and compare the bodies after removing only `traceId`.
- [story] Criterion 7 says “every request enum” and “every response timestamp” without naming the HTTP samples that exercise them. Enumerate the affected routes and fields, including the raise 201, transaction list, history list, and detail; assert literal wire strings ending in `Z`, not merely parsed instants.
