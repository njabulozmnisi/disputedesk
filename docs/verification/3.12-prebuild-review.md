## Resolution

Product owner refine, 2026-10-30. Every point is folded into the story; no `[decision]` raised. Still 7 criteria.

- 409 split (medium): criterion 6 splits by `customerStatus` (`withdrawn` success, `resolved` the "now Resolved" notice, an open status the generic retry copy with the note kept, unknown the generic "can't be withdrawn" copy); the dialog is screen-owned and stays mounted (criterion 4); supervisor break added.
- 200 cache write (medium): `setQueryData` from the 200 body, then invalidate list and transactions; the 409-`withdrawn` path awaits the detail refetch; focus moves with `onCloseAutoFocus` and `preventDefault()`; one test asserts badge, absent button and `h1` focus together (criterion 6).
- Summary rows (medium): wrong-amount "Transaction amount" and "Expected amount" through `formatMoney` when `expectedAmount` is not null (criterion 2). Reference: removed, not shown in full. FR-17 requires no visible dispute reference, the customer's quotable reference is the problem notice's `traceId`, and a truncated GUID is not a reference a bank tool can look up. Removed from DESIGN.md (summary card and the Mono row) and the six detail mockups; the UX memlog records the change.
- Touches (medium): `e2e/tests/spa-dispute-status-badges.spec.ts` (QA stage, badge leads to the detail, `href` re-checked) and the `dispute-detail.spec.ts` comment.
- Time format: `formatToParts` in `en-US` plus the literal " SAST", with October and September instants pinned (criterion 3).
- Case-insensitive `returnUrl`: criterion 7 and Touches; the shared `returnUrlAfterSignIn` compares the lower-cased pathname, with `/Disputes/<guid>` and `/Transactions/<id>` cases.
- Initial focus: "Keep dispute" (Radix default, WAI-ARIA APG least destructive action for an irreversible action), not the note, matching the challenger; the mockup note is changed. The dialog is asserted by role and name (criterion 4).
- Pending Escape and Keep: both do nothing while pending; tested (criterion 4).
- Error ordering: the query error is checked before its data; 404 the not-found screen, any other error the problem notice (criteria 2 and 6).
- Banner: static, not a live region; reappearing on that history entry is accepted; above the summary, as the mockup shows; EXPERIENCE.md and the mockup's `role="status"` updated (criterion 2).
