## Browser walk (Playwright, 1280x800)

Pages: sign-in (`/ui/v2/login/loginname`), register, register password, verify. Reached through the SPA's Sign in link.

- Theme colours: the page's custom properties read `--theme-light-background-500=#f4f5f7`, `--theme-light-primary-500=#2b57c9`, `--theme-light-warn-500=#b42318`. Dark mode shows the #12171e card and #8caaf7 dot.
- Wordmark: both PNGs load (620 px wide, 200 from `/assets/v1/<instance>/policy/label/logo-...` and `.../logo-dark-...`); the light navy wordmark with cobalt dot shows with `prefers-color-scheme: light`, the pale one with the light-blue dot in dark. Screenshots: `docs/verification/2.6-qa/sign-in-light.png`, `sign-in-dark.png`, `sign-up-light.png`, `sign-up-dark.png`, `verify-dark.png`.
- Font: `ZitadelCustomFont` is loaded (`document.fonts` status `loaded`), body `font-family: ZitadelCustomFont, Lato`; `GET /assets/v1/<instance>/policy/label/font-...` -> 200 (RFC 9110). The glyphs are Nunito Sans.
- Console: no CSP violation or any other message except `GET /favicon.ico` 404 on `auth.localhost` (see F2). The mockup server's own favicon 404 is unrelated.
- Verification email: after the sign-up, Mailpit holds one message to `qa26@example.test`, subject "Verify email", from `noreply@disputedesk.test`, created at the second of the sign-up (P0-2 regression: pass).

Comparison with `docs/ux/mockups/sign-in.html` and `sign-up.html` (screenshots `mockup-sign-in-*.png`, `mockup-sign-up-dark.png`): the wordmark, primary colour, background family and text colour match. The shapes differ, as the mockup banner and the story's Boundaries say (the label policy has no radius or spacing fields): the card is square-cornered, the button grey (disabled) until filled, and the heading is the foreground colour, not the mockup's navy `--heading`. The headings and button text are synthesised bold from the single 400 file, as documented.

## Findings

- F1 (medium, intermittent): on the first fresh `down -v` + `up --build --wait`, `provision` exited 1 and failed the start: `FAIL GET /admin/v1/policies/label/_preview -> 503 {"code":14, "message":"connection error: ... dial tcp [::1]:8080: connect: connection refused"}`, 0.5 s after Zitadel logged "server is listening" (05:32:52.74 listening, 05:32:53.23 failure), although `zitadel ready` already reported healthy. Re-running `docker compose up provision` succeeded, and two further fresh starts (the second `down -v`, and the one after `infra/smoke.sh`'s own `down -v`) passed, so it is about 1 in 3 here. The story's first admin call is now the label-policy preview, before the old first call (`/auth/v1/users/me`); I did not run the base to see whether that call races the same way. The story's rule (no 400 or 5xx tolerated) is deliberate, so the fix is a bounded retry or wait for the first call in `provision.sh`, a supervisor decision. Not a criterion failure: criterion 3 says any status of 400 or above fails the run.
- F2 (low, outside the story): `auth.localhost/favicon.ico` is a 404, logged as a console error on every hosted page. No icon is uploaded by design (Boundaries: Login v2 never reads `iconUrl`).
- F3 (low, copy): the hosted pages say "Create your Zitadel account." and "Welcome back!"; the mockups say "Sign in to DisputeDesk". Copy is not a label-policy field, so it is beyond this story.
- Note: `infra/smoke.sh` ends with `docker compose down -v` (removes this project's volumes), so a QA run that calls it must bring the stack up again afterwards; I did.
