## 3. Verdict

KISS and the standards rule are applied consistently in these three projects. Every non-obvious mechanism cites its source in the code (Microsoft Learn, an RFC, OWASP, the PostgreSQL docs or an AD). Each raw-SQL statement is one named Infrastructure method with its reason in the remarks. Every single-implementation interface is on the AGENTS.md list, and there is no repository layer, mediator or mapper. The heavy designs (event-sourced disputes with a read model, the idempotency lease, the outbox relay, linking) are heavy because a decided requirement asks for them, and each was challenged and recorded. I found no home-grown mechanism that replaces a framework built-in, so nothing is high severity. What is left is local: copy-paste past the third case, one-caller helpers, dead members, and one defensive branch that hides a misconfiguration.

Top three to change:

1. **CORE-1.** Fail the Worker at start-up when the connection string is missing, with `ValidateOnStart`, as it already does for Kafka. Today the relay loops with a fresh heartbeat, so a broken deployment looks healthy.
2. **CORE-2, CORE-3, CORE-4.** Give the use-case instant cut, the dispute not-found error and the money format one home each. These are copied 5, 4 and 3 times, and the copies have to stay identical for AD-4 and AD-11 to hold.
3. **CORE-5 with CORE-6.** Give the three replay-and-retry handlers one load shape and a plain clash signal: drop the one-caller `DisputeReplay` and its extra `MAX` query, and replace the `Result<T>?`-null convention with the EF Core catch-reload-retry shape.
