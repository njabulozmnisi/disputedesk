## 3. Verdict

The 2:1 test-to-production ratio comes mostly from thorough criterion coverage, not from a bespoke framework. The test infrastructure is mostly the documented stack (xUnit v3, `WebApplicationFactory`, Testcontainers, EF Core interceptors, Playwright projects), used plainly and without inheritance. Where it drifts from the standard, it is in the observability and source-rule helpers, and in e2e copies that a shared helper already replaces.

Evidence:

- 800 backend test methods (583 Api integration, 89 domain, 58 worker, 70 architecture) and about 251 e2e tests cover about 343 Given/When/Then criteria across 52 stories. That is about 2.3 backend tests per criterion, which matches the mandated depth: "every endpoint is called in every authorisation state" (backend.md) and missing, wrong-type, out-of-range and oversized cases for each input (build-story step 3). Sampled tests map to named criteria in their summaries (for example "6.2 AC1, AC6 and AC7").
- Average size is about 32 lines per backend test method. Shared helpers and fixtures are about 4,400 of 25,800 backend test lines (17%), and most of that is fakes of real external systems and the interceptors that stage real failures.
- Setup duplication is low in the backend: each test starts its own `ApiFactory` on a fresh database, as the convention requires, through one or two helper calls. Duplication is heavy in e2e (TST-5).
- Flakiness by design is limited and mostly recorded: real-time rate-limit windows (framework limit), librdkafka timeouts, and a handful of absence sleeps (TST-6, TST-8).

Top three changes:

1. TST-1: replace the six `MeterListener` recorders and two log providers with `MetricCollector<T>` and `FakeLogger` from `Microsoft.Extensions.Diagnostics.Testing`. This is the largest standards gap and removes about 200 lines of hand-written listeners.
2. TST-4 (with TST-3): build test disputes through the aggregate methods, as `SweepRig.NewDispute` does, instead of hand-written streams that include transitions the domain refuses. Switch the Api tests' clocks to `FakeTimeProvider`.
3. TST-5 and TST-6: make the regression specs use `support.ts` (`signInContext`, `queryRows`, `expect.poll`) and replace `waitForTimeout` with signals. Then TST-2: move the source rules from regexes to a Roslyn syntax tree.

Unverified: nothing was built or run. The line counts and grep counts above were taken from the working tree on 2026-11-03. `Microsoft.Extensions.Diagnostics.Testing`, `Microsoft.CodeAnalysis.CSharp` and `Microsoft.CodeAnalysis.BannedApiAnalyzers` would be new packages and must pass AGENTS.md dependency verification before use.
