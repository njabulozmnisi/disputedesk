## 3. Verdict

The configuration layer follows the tools' documented mechanisms closely and consistently: Compose merge tags and
interpolation, nginx's official-image templating, SSM documents with `allowedPattern`, OIDC with exact subject matching,
write-only Terraform arguments, pinned digests everywhere. Nearly every non-obvious line carries its reason and source.
KISS slips in the test and verification layer. Each story added its own bash harness and its own adversarial cases,
so infra now has about 2,000 lines of hand-written shell tests. Some of them parse HCL, YAML or CSS with regexes, and
some cover the same behaviour two or three times. Meanwhile the standard linters every story requires (`actionlint`,
`shellcheck`) are not in CI. The Terraform module split and the live OIDC re-check are the two places where an AD or
human decision itself adds structure that one dev environment does not need.

Top three changes:

1. **INF-1 and INF-9:** one infra test harness (the ad-011 `infra/tests/` project or bats-core), one owner per behaviour,
   and no copied helpers.
2. **INF-3:** set the forwarded headers once per nginx server block. This removes about 80 repeated lines across the two
   templates.
3. **INF-6** (a decision): flatten the seven single-use Terraform modules into one root with a file per concern. Raise
   INF-7 and INF-8 in the same human review.
