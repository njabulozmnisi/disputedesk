## 3. Verdict

The feature code is mostly by the book and readable. Forms on the linking and raise screens follow the AD-31 pattern. Problem routing, money, dates, telemetry and accessibility each cite a standard, and deliberate limits carry `// shortcut:` markers. The duplication is mostly below the third-case threshold.

The exception is session end. The ASVS requirement is real, but the extra requirement that the session-ended screen show offline, with no navigation, turned it into the hardest part of the codebase to follow. It is spread over five modules, needs late-response guards in seven handlers, and depends on test scaffolding that patches the route tree and forces garbage collection. It took story 7.14 seven fix briefs and six verify runs, and it still leaves IDs behind (P74). The second root cause is the reactive component gate (`SessionGate`). Because it redirects on every cache change, much of that ordering logic exists only to stop it racing the session-end navigation.

The smaller misses are deferrals that never came back: the withdraw form outside RHF and zod, the error-summary copies, and the duplicate zod config. The "refactor sweep" they were deferred to was never scheduled.

Top three changes:
1. **FE-1 [decision]:** end a session with a document navigation (`location.replace`), as the bfcache restore already does, and delete the in-place clean-up machinery and its tests.
2. **FE-2:** move session gating into TanStack Router `beforeLoad` plus `redirect` on pathless layout routes, with the `queryClient` in router context.
3. **FE-3 and FE-4:** rebuild the withdraw note on React Hook Form plus zod, and move both inline error summaries onto `ErrorSummary`. Schedule the deferred sweep, or stop deferring to it.
