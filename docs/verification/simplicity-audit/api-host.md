## 3. Verdict

KISS and the standards rule are applied consistently and with discipline across this file set. Almost every non-trivial mechanism is the framework's built-in way: OIDC and cookie handlers, `ITicketStore`, `IAuthorizationMiddlewareResultHandler`, the built-in rate limiter, Forwarded Headers, ProblemDetails, OpenAPI transformers, `IMeterFactory` and `TimeProvider`. Each one cites its Microsoft Learn page, RFC or ASVS item in a comment, and each departure from a default is tied to an AD, a story decision or a pinned test. The two genuinely custom mechanisms are justified by an adopted standard with no .NET implementation: the RFC 9651 Idempotency-Key parser and the antiforgery filter. No high-severity finding; the issues found are consistency and leftover shape, not invented mechanisms.

Top three to change:
1. **API-1**: settle on one enum-reading rule for the API and delete one of the two converters (a human decision between 2026-10-29 and 5.2 AC3).
2. **API-2**: replace the `Operations:Actors` map, whose only legal value is a constant, with a set of subs (amend AD-9, AD-26 and ad-006).
3. **API-3**: merge linking's three Add and three Map calls into one pair per side, with both handlers registered in one place, matching the other features.

Also watch the `AcceptsMetadata([])` line in `OperationsEndpoints.cs:60`. It is accepted, but it relies on ASP.NET Core routing source rather than documentation, so re-check it on each framework update.
