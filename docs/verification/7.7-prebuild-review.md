## Checked and correct

- **Outbox schema:** `OutboxMessages` has `Id` (uuid), `DisputeId`, `DisputeVersion`, `Status` (text: `Pending`, `Sent`, `Failed` through `HasConversion<string>()`), `Attempts`, `NextAttemptAtUtc` (timestamptz) and `LastError` (migration `AddDisputes`; no later migration changes the table).
- **Relay:** the head query takes `Pending` rows due now with no earlier unsent version, so a `Failed` head holds back its successors and a released row is picked up with no Worker restart (10 s idle wait). The 5th `Rejected` refusal sets `Failed`; the `Failed` log line carries `EventId` and `DisputeId`; `disputedesk.outbox.failed` exists; `MsgSizeTooLarge` is a refusal.
- **Topic:** `disputedesk.disputes` has 3 partitions keyed by dispute ID, so step 4's offset comparison is within one partition.
- **Stack:** services `postgres`, `redpanda`, `core-banking`, `worker` exist; gateway 8080 fixed; `auth.localhost:8080`; Mailpit 8025; dashboard 18888; movable ports are `POSTGRES_HOST_PORT` and the `DISPUTEDESK_*_PORT` variables; `qa_readonly` exists with read-only sessions.
- **Operations and Scalar:** routes `GET /api/v1/operations/disputes/{disputeId}`, `POST …/start-review`, `…/escalate`, `…/resolve`; a second resolve gives 409 `action-not-allowed`; Scalar at `/scalar/`, scheme `bearer`, enabled only in Compose.
- **Core banking down:** `/health/ready` checks only migrations and Zitadel discovery; transactions and the raise return 503 `core-banking-unavailable`.
- **Seed data:** customers A to D and logins A, B, C in `fixtures/local.json` (C SIM-swap flagged, D no login); `TXN-A-0011` is the only `slaDemo` dispute, due 5 minutes after seeding.
- **Other references:** criterion 3's research facts match `dispute-lifecycle.md` and NFR-DOC-5; PRD §5.1 to §5.10, `.nvmrc`, `backend/global.json`, `scripts/operations-token.sh`, `scripts/secret-scan.sh`, P20 and P51 exist.
- **Size and design:** six criteria, three short documents using existing commands, no new mechanism; every mechanism is sourced.
