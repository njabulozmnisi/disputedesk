## Pre-mortem
- [story] A later proxied location adds one `proxy_set_header` and silently stops inheriting the server block, allowing a client-supplied `Forwarded` header upstream. nginx’s all-or-nothing inheritance rule makes this the principal maintenance risk.

## Simplest design
- [story] Move each server’s existing common directives to that `server`; remove them only from locations that inherit them. Keep the local `/otlp/` location’s own directives unchanged: it already overrides inheritance. Put the Mailpit-specific `Upgrade` and `Connection $connection_upgrade` directives in its server block. No include, variable, or new abstraction is needed.
- [story] Replace “complete set” for `/otlp/` with “its existing location-specific set.” Copying the app server’s `Host`, `X-Forwarded-Host`, or `X-Forwarded-Proto` directives there would change what its receiver gets today.

## Assumptions
- [story] Criterion 3 assumes every proxied route currently sends `X-Forwarded-Host` and `X-Forwarded-Proto`. The local `/otlp/` location does not set either; the AWS Mailpit location does not set `X-Forwarded-Host`. Preserve those exceptions rather than make the universal claim.
- [story] The story assumes 8.7’s unchanged tests prove every listed header on every route. Its criteria require per-route rejection of `Forwarded`, but do not require per-route comparisons of all the other forwarded values; 8.7 has not been built yet.

## Standards
- [story] No invented mechanism is needed. Use nginx’s documented [`proxy_set_header` inheritance](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header) and [`proxy_http_version`](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_http_version); do not introduce a custom header-sharing mechanism.
