**Fixes**
1. **First-screen detection (medium).**
   - `RootLayout` now holds a `FirstHeadingContext` ref in place of the consume-once callback.
   - `usePageHeading` stores its own `h1` there when the ref is empty (`firstHeading.current ??= heading`) and skips focus while its `h1` is that element. A route change mounts a new `h1`, so focus still moves.
   - New test in `routing.test.tsx`: "is the first thing Tab reaches on the first load even when effects run twice (StrictMode)", using `renderApp({ strictMode: true })`.
2. **`idsBeforeLoadMore` (low).**
   - `loadMore` is now async and clears the ref when `fetchNextPage` settles with `isError`.
   - The effect clears the ref as soon as the load has settled, whether or not a row was added. It skips while `isFetchingNextPage`, so an unrelated re-render mid-request does not clear it early.
   - New `describe.each` test in `DisputesScreen.test.tsx`, run twice: after a Load more that failed, and after one that brought only an unknown-status row. Each case checks that a later `invalidateQueries` refetch bringing a new dispute neither moves focus nor announces anything.
3. The route-change test now asserts `screen.getByRole('main').contains(document.activeElement)`.
4. `DisputeRow.tsx` uses `Object.hasOwn(reasonCopy, dispute.reason)` instead of the `Partial` cast.
5. `formatDate` is renamed `formatDayWithYear` in `format.ts`, `format.test.ts` and `DisputeRow.tsx`. No other references remain.

**Breaks, all verified to fail**
- **StrictMode test, before the fix:** it failed on the consume-once callback with `expect(element).toHaveFocus()` (the `h1` took focus, not the skip link). It passes after the fix. No patch was kept.
- **Failed-load case:** delete `if (result.isError) idsBeforeLoadMore.current = undefined;` at `DisputesScreen.tsx:87`. Then `DisputesScreen.test.tsx > Load more > after a Load more that failed > leaves focus alone and announces nothing when a later refetch brings a new dispute` fails (1 failed).
- **Unknown-status case:** move `idsBeforeLoadMore.current = undefined;` in the effect to after `if (!first) return;`. Then `... > after a Load more that brought only rows this build leaves out > leaves focus alone and announces nothing when a later refetch brings a new dispute` fails (1 failed).
