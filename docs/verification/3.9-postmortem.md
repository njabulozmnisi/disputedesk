# Postmortem: 3.9 second fix round, recurring flaky absence assertion

Trigger: a second fix round and a recurring escape category (flaky).

- What happened: `ListDisputesPagingTests` asserts a short literal (`abc`) is absent from the whole ProblemDetails body, which carries a random 32-hex `traceId`; it failed by chance on the re-verify run. The session fix had the same fault (`eyJ` in random cookie ciphertext).
- Stage that caught it: verifier (re-run). Stage that should have: reviewer, on the original diff.
- Category: flaky.
- Countermeasure proposed (a skill change, needs approval): a Known pitfalls line in review-story and build-story: "an absence assertion checks the field that could echo the input, or the body with random fields (`traceId`, ciphertext, IDs) removed, never a short literal against the whole body". A deterministic check is not practical (it would need to judge literal length and body shape).
