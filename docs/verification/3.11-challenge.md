## Pre-mortem

[story] SM-1 overcounts opens: the proposed parent-route `onEnter` can run before the cached-row guard in story 3.6 redirects an invalid or reloaded raise URL to `/transactions`. An open span would then represent a screen the customer never saw.

[story] SM-2 reports a longer interval than “open to 201”: criterion 2 ends the submit span when the mutation settles, while criterion 3 uses that end time as the 201 time. Response parsing, retries and mutation callbacks can extend it.

[story] Customer data reaches telemetry despite query stripping. The generated client also fetches `/api/v1/disputes/{disputeId}`; stripping `url.full`’s query does not make an identifier-bearing path safe.

## Simplest design

[story] Start one web tracer before render, register fetch instrumentation, and exclude non-API fetches. After the raise route’s existing cached-row guard succeeds, emit one immediately ended open span and retain its span context with that flow’s draft. Wrap each submit attempt—including its in-progress resends—in one active submit span linked to that open; record the **201 response time** separately from mutation settlement. Use the existing same-origin OTLP proxy and test the exported attributes and propagated headers. No new transport, hand-written `traceparent`, or general-purpose telemetry layer is needed.

[story] Count distinct opened flows with a linked successful submit, not raw `submitted` spans: story 3.6 permits Try again and a replayed 201 for the same draft.

## Assumptions

[story] The story assumes a parent-route entry means 4a was displayed. Story 3.6 instead performs its cached-row redirect inside the session gate, after route matching.

[story] It assumes the selected browser context manager preserves the active span across the antiforgery `await` **and** TanStack Query’s retry scheduling. Neither follows from testing only the first POST; assert parentage on every resend.

[story] It assumes `/otlp` accepts the chosen encoding. The earlier gateway smoke record reports a successful OTLP/HTTP **JSON** POST (`docs/verification/2.5-review.md`); that is evidence to reuse rather than an unanswered design choice.

## Standards

[story] No invented transport is required. Use [W3C Trace Context](https://www.w3.org/TR/trace-context/) through OpenTelemetry fetch instrumentation, [OpenTelemetry span links](https://opentelemetry.io/docs/specs/otel/trace/api/#link) for flow correlation, and the [HTTP semantic conventions](https://opentelemetry.io/docs/specs/semconv/http/http-spans/) for status and URL attributes. The story should name the documented instrumentation hook used to sanitize **all** emitted URL attributes, not imply that changing `url.full` alone is comprehensive.

## Gaps

[story] Criterion 3 needs an observable definition of “entered”: test a valid cached row, a missing/non-disputable row, 4a→4b→4a, and a fresh entry after leaving. Record an open only for the valid flow.

[story] Criteria 2–3 need separate assertions for one span per attempt, parentage of every POST, and the timestamp of the **201 response**; specify outcomes for exhausted in-progress resends and a failed antiforgery fetch before any POST.

[story] Criterion 4 needs a path-identifier case and checks for every URL-bearing attribute and event, including fetch spans outside the raise flow. Its listed seeded values and query-string assertion do not prove the stated “no personal data in any span.”

[story] Criterion 5’s CSP claim requires a browser check under the gateway CSP; an in-memory exporter and MSW cannot establish that the shipped SDK and context-manager code execute without a policy violation.

## Resolution

2026-10-30, Sofia (refine). Every point was `[story]`; all folded into `story-3.11-raise-screens-emit-browser-spans-that-join-the-api-trace.md`.

- Open over-count before the guard redirects: the open span comes from the raise guard's admitted branch, not `onEnter`; tests cover a valid row, a deep link, a not-disputable row, Back after submit, 4a → 4b → 4a and a fresh entry (criterion 4).
- SM-2 measured to mutation settle: SM-2 is read from the end of the POST fetch span with status 201 (a child of the submit span), minus the linked open span's start (criterion 4).
- Identifier-bearing paths: `sanitizeUrl` drops search and hash and replaces GUID path segments with `{id}`; criterion 5 adds a GUID path case, fetch spans outside the raise flow, and an attribute-key allow-list.
- Count distinct flows for SM-1: criterion 4 defines SM-1 as distinct open spans linked from a `submitted` submit.
- Context across the antiforgery `await` and retries: explicit `context.with` in `customFetch` and in the raise `mutationFn`; parentage asserted on every resend (criteria 2 and 3).
- Encoding: OTLP/HTTP JSON, from 2.5's smoke evidence (criterion 6).
- One span per attempt, exhausted resends and a failed antiforgery fetch: criterion 3 with a bounded `dispute.raise.outcome` set (`idempotency-in-progress`, `unexpected`).
- CSP needs a browser check: criterion 7 in `e2e/tests/dispute-raise.spec.ts`.
