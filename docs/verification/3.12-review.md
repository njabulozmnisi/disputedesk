### Item 1: focus after Try again (closed, with one gap)
The handler is now `void query.refetch().then((result) => { if (result.isSuccess) headingRef.current?.focus(); })`. I checked the three cases you asked about:
- **After a successful retry on a direct load**, focus moves to the heading. The page-heading hook doesn't focus the first page's h1, so this call is what fixes the lost focus.
- **After a failed retry** with a non-404 error, nothing moves focus. TanStack Query v5 keeps `isError` true while it refetches, so the error card and its Try again button stay on screen and keep focus.
- **On a route-change load** the handler doesn't run at all, because it only runs when someone presses Try again. On a route change followed by a successful retry, the hook's title-change effect also focuses the heading. Both calls target the same element, so this is harmless.

The new test, `moves focus to the heading after a successful Try again, as the button unmounts`, uses a direct load. Without the fix, nothing focuses the h1 when the title changes and focus falls to the body, so the test would fail. That matches the builder's observed failure, so it fails without its fix.

### Item 2 (closed)
Waiting for the notice makes the "a failure" case test the failure state. Before, it could press Tab while the page was still loading, since both states read "Dispute". There was nothing to fix in the code, so no test could fail first.

### Item 3 (closed): the assertion is meaningful
The test is a direct load, so the page-heading hook does not move focus here. The builder's explanation ("the existing heading effect already covers it") is wrong. What actually moves focus:
1. The 404 removes the loaded card, which unmounts the withdraw dialog.
2. The dialog's close-focus handler (`WithdrawDialog.tsx:281-283`) cancels the dialog library's default focus and calls `returnFocus`.
3. `returnFocus` (`DisputeDetailScreen.tsx:127-129`) finds no Withdraw button, so it focuses the heading.

So the new assertion guards the heading fallback in `returnFocus` on the 404 path. If that fallback were removed, focus would end on the body and the test would fail. It passed without a code change because round 1 already behaved correctly, and it is still worth keeping.
