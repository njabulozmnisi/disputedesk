- `squash_merge_commit_message` is one of `PR_BODY`, `COMMIT_MESSAGES` or `BLANK`.

**Read-back command.** A GET as the owner of exactly the seven fields, with a table of expected values.

**README.** It has both commands with the owner-token prefix, the committed file, the seven values, and why there is no linear-history rule and no merge queue. The linear-history reason is supported by *Available rules*: "any pull requests merged into the branch … must use a squash merge or a rebase merge". The merge-queue reason quotes ad-012 clause 2 word for word.

**Test.** The README case greps each command line exactly. Break `b3` (`-f` for one boolean) fails it.
