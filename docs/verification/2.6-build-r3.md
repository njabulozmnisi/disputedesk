# 2.6 build, fix round 3

Built on the M1 at 594aa79 (main) with 2.6-r2 applied; patch scratchpad/lanes-2.6r3/2.6-r3.patch.

Fix round 3 for story 2.6 is built and nothing is committed. Both items are done, and the deliberate break showed the new CI case failing before the fix and passing after it.

**Base.** I checked out `594aa79` (origin/main), applied the round 2 patch with docs excluded, and `dotnet build -warnaserror` had 0 errors.

**Item 1, `label-policy.sh` `colour()`.** The match now allows optional whitespace between the token name and the colon. I applied the same change to the `sed` that pulls out the value. Without it, a single valid `--primary : #2b57c9` would match but then be rejected as "not #rrggbb". CSS Syntax Level 3 treats that form as an ordinary declaration, so it should be accepted, and this is still within item 1's parsing scope. I added a one-line comment citing the spec.

**Item 2, the CI rejection step.** I added one case:

`rejects "a twice-declared token with a space before its colon" 's/--primary: #2b57c9;/--primary: #2b57c9; --primary : #000000;/' --primary`

- **Unfixed script:** the step stops at the new case with `::error::accepted a twice-declared token with a space before its colon` and exits 1. Run directly, the generator accepts the file and prints the policy body.
- **Fixed script:** all 9 cases print `ok`. The new one reports `--primary is declared 2 times in the light block, not once`.
