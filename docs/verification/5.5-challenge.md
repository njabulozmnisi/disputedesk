VERDICT: SIMPLIFY

## Pre-mortem
- [story] Scalar works through the Api but fails through nginx: the gateway currently sends `/scalar/` to the SPA, and the proposed `location /scalar/` would still leave the existing `/scalar` test path there.
- [story] The page loads but cannot be used: a fixed script hash does not cover inline styles or a changed Scalar script, and declaring `clientCredentials` may expose a browser flow that `connect-src 'self'` deliberately blocks.

## Simplest design
- [story] Bind and validate one `Scalar:Enabled` option; map the existing Scalar and OpenAPI endpoints only when enabled. Use the documented OpenAPI transformers for the two schemes and operations-only requirements, then proxy both Scalar paths and the document through nginx with one Scalar-specific header include. No custom authentication flow, credential injection, nonce service, or new API abstraction is needed.

## Assumptions
- [story] The served Scalar page has one stable inline script. AD-26 states this, but neither the existing `Program.cs` mapping nor `ApiReferenceTests` proves it; hash every served inline script rather than assuming a count.
- [story] Operators will use only the pasted-bearer path. The document also advertises an OAuth client-credentials flow, so verify that Scalar does not attempt that flow or retain credentials in browser storage.

## Standards
- [story] No invented mechanism is required: [ASP.NET Core document and operation transformers](https://learn.microsoft.com/aspnet/core/fundamentals/openapi/customize-openapi?view=aspnetcore-10.0) and [CSP hash sources](https://www.w3.org/TR/CSP3/#grammardef-hash-source) cover the design. Encode “either scheme” as **two separate Security Requirement Objects**; putting both schemes in one object means **both** are required under [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0#security-requirement-object).

## Gaps
- [story] Criterion 1 does not settle `/scalar` versus `/scalar/` at the gateway, although today's tests request `/scalar`. Specify the redirect or proxy behavior, including when the switch is off.
- [story] Criterion 3 should assert the exact OR-shaped security array on every operations operation and its absence elsewhere, not just the presence of two schemes.
- [story] Criterion 4 checks the page's hash and ordinary headers but not a rate-limited Scalar response; nginx currently routes 429 through `@rate_limited`, which sets the SPA header include. State which CSP a Scalar 429 must carry and test it.

## Resolution

Sofia, 2026-10-30. Story 5.5 is refined to six criteria. The human settled two points on 2026-10-30: the document declares only the `bearer` scheme (decision 1), and `style-src 'self' 'unsafe-inline'` holds on the Scalar locations only (decision 2); AD-26 records both.

- Pre-mortem, `/scalar` versus `/scalar/` at the gateway: criterion 4 (an exact `location = /scalar`, which gets the Api's 302 to `scalar/`, a prefix `location /scalar/`, and the same requests reaching the Api's 401 when the switch is off).
- Pre-mortem, inline styles and a changed script: criterion 5 (`style-src 'self' 'unsafe-inline'`, decision 2) and criterion 6 (the hash test fails on any script change). The browser flow for `clientCredentials`: dropped by decision 1.
- Simplest design: criteria 1, 3, 4 and 5 (one bound option, built-in transformers, one header include); the second scheme and its transformer are dropped by decision 1.
- Assumption, one stable inline script: criterion 6 asserts exactly one inline script and exactly one hash in the template.
- Assumption, operators use only the pasted bearer: decision 1 removes the client-credentials flow from the document; criterion 2 asserts `persistAuth` absent or false, and a supervisor check reads `localStorage` after pasting.
- Standards, two Security Requirement Objects for "either scheme": dropped by decision 1; criterion 3 asserts exactly `security: [{"bearer": []}]` on each operations operation.
- Gap, criterion 1 path: criterion 4 (above).
- Gap, criterion 3 exact security array and its absence elsewhere: criterion 3.
- Gap, the CSP on a Scalar 429: criterion 5 (the unchanged `@rate_limited` response with the SPA's CSP and each header once; `infra/smoke.sh` checks a 429 on `/scalar/`).
