## Findings

### L1 (low) The 5.3 automation guard still exempts `DisputeWire.cs`, which no longer names `ActorType.Automation`

`backend/tests/DisputeDesk.ArchitectureTests/SourceRulesTests.cs:52` (the `allowed` entry) and its summary at `:40-42`
("The wire mapping in `DisputeWire.cs` only translates a recorded actor type for the outbox and the operations read").
Criterion: story 5.3 AC8 / AD-14a, "only the SLA sweep and the seeder name `ActorType.Automation`, so no HTTP path can
record an automation actor", and the guardrail rule (never weaken a guard). The mapping that justified the exemption is
deleted by this story's criterion 4, so the guard now admits an `ActorType.Automation` in `DisputeWire.cs`, an
Application file on the HTTP paths, and its summary is false. No current violation. The builder named it and left it
for the lows batch to avoid renaming a test earlier records cite. Fix: drop the `DisputeWire.cs` entry and the
summary's last sentence (the method name can stay, or be renamed with the citing records noted).

### L2 (low) AD-1's "Contracts references Domain only for the enums" has no check

`backend/tests/DisputeDesk.ArchitectureTests/LayerTests.cs:36-43`. Criterion: AD-1, "Contracts references Domain only
so that its records use the Domain enums that are identical on the wire"; known pitfall (3.8) "an invariant a design
decision relies on must be enforced in code and proved by a test". Today Contracts uses exactly the nine enums (metadata
check above), but nothing stops a later Contracts record from taking `Dispute`, `Error` or `TransactionSnapshot`:
`ContractsAssembly_References_OnlyDomainOfTheSolution` checks the assembly, not the types. Criterion 1 asked only for
the assembly rule, so this is not a gap in the story. Fix (lows batch): a reflection test that every Domain type used
in a Contracts public signature is an enum.

### L3 (low) Leftover root-qualified names where no clash remains; the AC6 exemption is file-wide

Criterion: `docs/conventions/backend.md:14`, "Only where a Contracts type and a Domain type still share a name does a
file import one side and write the other qualified". After this story no Contracts type shares a name with a Domain
type, yet `Application/Disputes/WithdrawDispute/WithdrawDisputeHandler.cs:23,24,64,104` and
`Application/Disputes/GetDispute/GetDisputeHandler.cs:16` still write `Contracts.Disputes.DisputeResponse` /
`WithdrawDisputeRequest`, as do tests (`DisputeWireErrorTests.cs:18,30,44`, `StoredEventReplayTests.cs:168`,
`RequestBodyPrivacyTests.cs:31,33,34`, `PublishMappingTests.cs:145`), while the same qualification was removed in
`CustomerView`, `OperationsView`, `RaiseDisputeHandler` and `CommitRows`. These are not the nine enums, so criterion 6
itself is met. Separately, `BackendSource_EnumIdenticalOnTheWire_IsNeverNamespaceQualified` exempts the whole of
`RaiseDisputeRequest.cs`, so a second qualified enum name added to that file would pass. Fix (lows batch): write those
names through their `using`; narrow the exemption to the one expected node (assert exactly one hit in that file).
