## The builder's conflict: `User-Agent: DisputeDesk-PlatformTests`

Inputs: "Each fetch: HTTPS only, no redirect, **no credential, cookie or extra header**, 10 s to connect (`SocketsHttpHandler.ConnectTimeout`), 30 s in all, at most 2 retries".

The client sends exactly one header beyond what `HttpClient` sends by itself, `User-Agent: DisputeDesk-PlatformTests` (`ServiceReference.cs:31`), and `Fetch_ValidFiles_...` and `CreateClient_HasTheBoundsInTheStory` assert that the request and default headers are exactly `User-Agent`. Read literally, that is an extra header, so the code departs from the written input. I confirmed the reason: the reference answers 403 to a request with no User-Agent and 200 with this one, so the literal input cannot be met by any working check. The input's intent, carried from 7.16 (whose `curl` sent its own `User-Agent` and `Accept`), is that nothing identifying or authenticating is sent; a fixed product token (RFC 9110, section 10.1.5) carries neither a credential nor a cookie, and the security record accepts it.

So it is a finding against the story's wording, not against the code: **L1**, low. The fix is in the story (Sofia, no human gate), not in the diff: Inputs should read "no credential, cookie or header other than a fixed `User-Agent` product token (the reference answers 403 without one; 7.16's curl sent its own)". The code and its exact-header assertions stay as they are.

## Findings

- **L1 (low), story wording, `ServiceReference.cs:31`.** Inputs: "no credential, cookie or extra header". The client sends `User-Agent: DisputeDesk-PlatformTests`, because the reference answers 403 without one (confirmed with curl, 2026-11-05). Not a code defect. Fix: the story's Inputs allow a fixed `User-Agent` product token and say why; the code stays.
- **L2 (low), missing bound assertion, `IamNamesTests.cs:10`.** Inputs: "the whole check, retries included, is bounded at 5 minutes by one cancellation deadline of the test's own". The deadline mechanism is proved with 100 ms deadlines, and every other bound (30 s, 10 s, no redirect, no cookies, no credentials, 2 retries) is asserted as a value in `CreateClient_HasTheBoundsInTheStory`, but `ServiceReferenceFixture.Deadline` is private and no test reads it: changing it to 50 minutes keeps every test green. Fix: make it `internal` and assert `TimeSpan.FromMinutes(5)` beside the other bounds.
- **L3 (low), docs inaccurate, `infra/terraform/README.md:30`.** Criterion 8 (the docs name the new check). The paragraph says "The mocked Terraform tests pin each rendered policy", but the compute trust policy is pinned by no Terraform test, and the four pins compare `.Statement` only, not `Version`. The equivalence check above shows no meaning changed; the sentence overstates what guards it. Fix: "pin each rendered policy's statements, except the compute trust policy, which has no placeholders; `IamNamesTests` pins every `Version`".
- **L4 (low), stale references to deleted files.** `infra/terraform/envs/dev/tests/deploy_role.tftest.hcl:2` still says "The policies are written with jsonencode" (the story forbids editing `*.tftest.hcl`, so this waits for the epic's lows), and `scripts/verify-with-copilot.sh:38` still allowlists `shell(infra/terraform/iam-names.test.sh)` (outside the story's Touches). Both recorded by the builder. Fix: in the epic-8 lows batch, update the comment and drop the allowlist entry.

No high or medium finding, so no fix round. The four lows go to `docs/verification/epic-8-lows.md` at merge.
