## 1. Pre-mortem

- [story] A second likely failure is navigation that looks correct but does not type-check or reach the intended not-found screen: `/disputes/<disputeId>` has no registered route until 3.7. Prove the `Link` compiles and test a click, not just its `href`.

## 2. Simplest design

- [story] In `TransactionRow`, render one trailing control: a status `Link` when both dispute fields are present, otherwise the existing Dispute link when disputable, otherwise the existing hint. Map the five `CustomerStatus` values in one exhaustive switch, using existing theme tokens. No new API call, cache, state machine, or generic badge system is needed.
- [story] Do **not** remove the `alreadyDisputed` switch case from `notDisputableHint`: it currently returns no hint, which is still the required result. Remove its obsolete shortcut comment and test the badge/no-hint combination instead.

## 3. Assumptions

- [story] The two dispute fields always arrive together. Both the generated contract and AD-13 promise this, but TypeScript represents them as independently nullable; specify what the row does if a response violates that invariant rather than showing a Dispute control for an already-disputed row.
- [story] A neutral treatment for plain “Resolved” is acceptable. The story supersedes outcome-specific row text, but `DESIGN.md` and the mockup still specify success/danger treatments only for outcome-specific resolved badges. State the intended tone and icon, and identify the outdated mockup examples as superseded.

## 4. Standards

- [story] No invented mechanism is necessary. Use the existing [TanStack Router `Link` navigation pattern](https://tanstack.com/router/latest/docs/framework/react/guide/navigation), [TypeScript `never` exhaustiveness check](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#exhaustiveness-checking), and theme tokens. Make the switch’s default consume `unreachable` and fail explicitly at runtime; a bare unused assignment may fail lint, while an unknown API value should not become a blank badge.

- [story] Criterion 1 says “styled as” a mockup that displays outcome-specific resolved text, contrary to its own plain-“Resolved” decision. Specify the superseding visual treatment and a testable narrow-width/reflow expectation.
- [story] Add a click-and-not-found test for the badge, plus a test that an already-disputed row has neither a Dispute control nor a hint. The existing row test expects **no link** for `alreadyDisputed` and will need to change.
- [story] State the expected handling of a missing `disputeId` or `customerStatus`, and bound the link parameter to the API’s dispute-ID format. These are the only new response inputs; the story currently names neither boundary nor malformed-pair behaviour.
