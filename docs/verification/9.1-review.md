**Compose download retry.** The curl manpage says `--retry` retries transient errors with a doubling backoff starting at one second. `--retry-all-errors`: "Retry on any error". "Before retrying, curl removes data that the failed attempt wrote to an output file set with `--output`". The script writes with `-o`, so a partial file can't reach `sha256sum`, and a bad file fails the checksum anyway.

One note, not a finding: `--max-time` "is reset each time the transfer is retried", so the worst case is 4 × 300 s plus backoff, about 20 minutes. That exceeds `platform`'s 15-minute job timeout. A download that slow fails the job either way, and the story fixed these flags.

## Findings

- **L1, low.** `scripts/ci-gates.sh:18`: a scalar `needs:` makes the step name the wrong job.
  - Criterion 8: "naming each job missing from or extra in the gate's `needs`".
  - `.jobs[GATE].needs[]` yields nothing when `needs` is a string. *Workflow syntax* (`jobs.<job_id>.needs`) allows this: "It can be a string or array of strings".
  - So a gate written `needs: b` in a workflow with jobs `a` and `b` fails naming both `a` and `b` as "not in gate's needs", although `b` is in it (I probed this).
  - The step still fails, so this is no gate bypass, but the message is wrong.
  - Fix: read `needs` as `.jobs[GATE].needs | ([] + .) | .[]`, or fail with "needs must be a list", and add a test case.

Not a 9.1 finding: `docs/process/agentic-sdlc.md:124` still draws the "docs-only push: floor guard, gitleaks, forbidden terms only" box. That is false once 9.1 merges, but Sofia placed it in 9.4's human-approved rule diff (pre-build finding 9), because it is a process document.
