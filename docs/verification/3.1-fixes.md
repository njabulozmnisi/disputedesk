Every stage's findings for the 3.1 commit, for one fresh fix builder. Builder worktree: `.claude/worktrees/agent-a9b34c26d4b48254f`.

## From the builder's report (decided by the human, 2026-10-28)

1. **Event timestamps end in `Z`.** The CloudEvent `time` and the data's `occurredAt` serialise as `...+00:00`; the consistency conventions say UTC with `Z`. Make both serialise with `Z`, and keep the committed sample and the schema test in step.
2. **Raise body bounds in `openapi.json`.** The `maxLength`, `minLength` and `pattern` attributes sit on the record's constructor parameters, which the OpenAPI generator does not surface. Retarget them (`property:`) so the generated `openapi.json` documents the bounds, and leave the validation behaviour and its tests unchanged.
3. **Pin `JsonSchema.Net` 9.4.1**, not 9.5.0 (published 2026-10-25, three days before the build). Reason: a short wait after a release guards against a compromised new version, and the test project needs nothing from 9.5.0.

No change: `IAppDbContext.Entities<TEntity>()` stays; AD-2 is amended.

## From the verifier (FAIL, criterion 2; `3.1-verify.md`)

4. **Comma-separated enum names bind.** `JsonStringEnumConverter` accepts `"a, b"` for any enum, `[Flags]` or not, even with `allowIntegerValues: false`. Reproduced by the supervisor on .NET 10.0.402: `"duplicateCharge, wrongAmount"` binds as `NotReceived` (a dispute under a reason the caller never gave), and `"wrongAmount, cancelledSubscription"` binds as the undefined value `6`, which throws in `DisputeWire.cs:20` and returns 500 instead of 400. Fix it once, in the shared `DisputeDeskJson` options, so every enum on the wire accepts exactly one defined member name and anything else gets 400 `validation` before the lookup. Check Microsoft Learn for a built-in option first; if none exists, say so in the report and keep the custom piece as small as the shared converter allows. Tests: both strings above on the raise endpoint, and a unit test on the shared options for a comma-separated value and an undefined name.

## Decided by the human after the reviews (2026-10-28)

5. **409 `already-disputed` carries the existing dispute.** AD-13: "a customer 409 carries `customerStatus`". Add `disputeId` and `customerStatus` extensions to the raise's 409 `already-disputed`, in both paths: the check before the save and the concurrent loser (after the unique violation, re-read the winning dispute through the ownership filter). Ownership is checked first, so it is always the caller's own dispute. Tests for both paths.

## From the reviewer (`3.1-review.md`)

6. **No `null` in enum components (medium).** The built-in OpenAPI generator adds `null` to a shared enum component when any usage is nullable: `CustomerStatus` and the earlier `NotDisputableReason` now list `null`, so non-nullable usages read as nullable and a nullable usage's `oneOf [null, $ref]` matches null twice. Add a schema transformer (`AddSchemaTransformer`, Microsoft Learn "Customize OpenAPI documents") that keeps `null` out of enum components, regenerate `openapi.json`, and add a test that no enum component lists `null`. It also clears `[Required] Reason?` reading as nullable.
7. **`Currency` is not fixed-length.** `IsFixedLength()` gives `character(3)`, which space-pads (PostgreSQL wiki, "Don't use char(n)"). Use `HasMaxLength(3)` only (`varchar(3)`) and update `DisputeSchemaTests.Disputes_Currency_IsAThreeCharacterCode`.
8. **Never hand-edit a generated migration.** Mark `[**/Migrations/*.cs]` as `generated_code = true` in `backend/.editorconfig` (Microsoft Learn, code analysis configuration, generated code), then delete and regenerate `AddDisputes` unedited (it is unmerged; AD-2's regenerate rule). This regeneration also carries item 7.
9. **Detach the losing raise.** After a `UniqueViolationException` the scoped context still tracks the losing `Dispute`, `TimelineEntry`, `AuditLogEntry` and `OutboxMessage` as Added, so any later save on that context (story 3.2 stores the 409 that way) re-inserts them and returns 500. Detach them when the violation is caught (EF Core change tracking, `EntityState.Detached`), and prove it with a second save on the same context after a lost race.

Not changed: the 422 `reason` extension serialising the Domain enum (nit; a test pins the names).
