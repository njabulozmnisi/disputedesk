## Pre-mortem

- [story] The local smoke check loses real-stack coverage of Scalar and OpenAPI. `GatewayTests` uses an echo upstream, but `smoke.sh` currently checks the actual `/scalar/` routes and the runtime document’s same-origin server URL before its Scalar section is removed.
- [story] An edge-header regression reaches production because coverage is split rather than consolidated: the retained identity-origin section of `smoke.sh` still asserts gateway-added security headers already exercised by the proposed gateway tests.

## Simplest design

- [story] Use one xUnit fixture for the two gateway images, their upstreams, clients and throwaway network; assert the existing harness’s observable responses there. Keep only real-stack wiring checks in `smoke.sh`, including Scalar/OpenAPI behavior the echo upstream cannot prove. Do not build a second generic test framework around the process helper.
- [decision] Keep root `docker-compose.yml` cases in the backend architecture tests and parse Compose JSON there. Moving `Compose_Api_StartsAfterTheGatewayThatHoldsTheIssuerAlias` into infra tests contradicts [ad-011 change 4](docs/decisions/ad-011-team-folders-in-one-repo.md), which explicitly assigns root-file cases to backend.

## Assumptions

- [story] The planned network subnet is available. The current harness fixes `192.0.2.0/24`; another Docker network using it would prevent fixture startup, independently of gateway behavior.
- [story] The CI time budget accommodates 504 cases. The existing harness tests 429, 413 and 502, but not 504; neither gateway template sets a shorter proxy read timeout, so inducing 504 may require nginx’s default wait on each image.

## Standards

- [story] No new gateway mechanism needs invention: use [xUnit class fixtures](https://xunit.net/docs/shared-context), [Compose’s JSON render](https://docs.docker.com/reference/cli/docker/compose/config/), and [nginx’s documented proxy timeout](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_read_timeout). The process helper should drain both redirected streams while waiting and enforce its timeout using [Process.WaitForExitAsync](https://learn.microsoft.com/dotnet/api/system.diagnostics.process.waitforexitasync); a helper that waits before reading risks blocking on full output buffers.
