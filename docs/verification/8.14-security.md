## Migration (Up and Down)

- **Up** drops `IX_Disputes_SlaWarning`, then `Disputes.SlaWarningRaisedAtUtc`. Nothing else: no `StoredEvents`, `OutboxMessages` or `AuditLogEntries` change, so the only data lost is the dropped column, which AD-22's pre-release rule allows (every database is recreated).
- **Down** is identical, call for call, to `AddSlaWarning.Up` (compared side by side): `AddColumn<DateTimeOffset>` `timestamp with time zone`, `nullable: true`, then `CreateIndex` on `SlaDueAtUtc` with the filter `"SlaWarningRaisedAtUtc" IS NULL AND "Status" IN ('Submitted', 'UnderReview')`. A rolled-back column comes back all null; that is the only reading of a dropped column and is what `migrations add` generates.
- The `DropSlaWarning.Designer.cs` target model equals the new `AppDbContextModelSnapshot.cs` apart from the class header, and the snapshot diff removes exactly the property and the index. `DisputeSchemaTests` pins the column's absence and the exact `pg_indexes` set. Mechanism: EF Core migrations (Microsoft Learn, "Migrations overview" and "Managing migrations"). The builder's round trip (`database update AddSlaWarning` and back) is the verifier's to re-run; not repeated here.

## A leftover `SlaWarningRaised` row is refused, never mis-read

- `StoredEventRow.TypeNamed` is a closed switch with `_ => null`; with the entry gone, the name is unknown. `ToStoredEvent()` throws `InvalidOperationException` before any deserialisation, so the row's `Data` is never read into another type.
- Action paths (`WithdrawDisputeHandler`, `OperationsActionHandler`, the sweep's `LoadStreamAsync`) call `ToStoredEvent()` on every row, so replay refuses the dispute. `Replay_RowOfAnUnknownEventType_ThrowsRatherThanReturnADisputeOrNotFound` is now a theory with an `"SlaWarningRaised"` case (ran, passed).
- Read paths (`GetDisputeHandler`, `ReadDisputeHandler`) filter on `HasKnownEventType` before reading data, so a leftover row is left out of both the customer and operations timelines, never shown under another type (AD-13, unchanged; `StoredRowSkipTests`, `ReadDisputeTests`).
- In the sweep the refusal is caught per dispute inside its savepoint and logged as `LogDisputeFailed(disputeId, exception.GetType().Name)`: a dispute ID and a type name only, never the exception message (which names the event type and row ID, no personal data either way).
