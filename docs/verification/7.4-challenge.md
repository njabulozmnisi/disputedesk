## Pre-mortem
- [decision] Public, anonymous `/otlp/v1/*` POSTs generate unbounded X-Ray and CloudWatch ingestion costs. The story itself identifies this unresolved AD-29 assumption; a 1 MB body cap and per-IP rate limit do not bound aggregate volume. Decide whether to accept anonymous ingestion or change the edge design before building.
- [story] The AWS override appears valid in isolation but retains local Compose behavior: the base file still defines Postgres and Aspire, publishes development ports, and contains fallback credentials. Explicitly account for merged services, dependencies, ports, and interpolation.

## Simplest design
- [story] Use one AWS override, one AWS nginx template, one Collector config, and the documented SSM Data Protection provider selected by configuration in the existing BFF registration. Keep local Compose and Postgres key storage unchanged. Do not add a credential proxy, configuration framework, or extra telemetry service.
- [story] Reuse nginx’s [realip module](https://nginx.org/en/docs/http/ngx_http_realip_module.html) to parse `CloudFront-Viewer-Address`, including its port, rather than inventing a port-stripping mechanism.

## Assumptions
- [story] Redpanda works with `--memory=512M` and the stack fits a 3.4 GiB limit. AD-28 explicitly marks this unmeasured; limits also need to cover simultaneous running containers, not just the steady-state total.
- [story] Local render checks predict AWS operation. They cannot establish instance-role access to SSM/KMS, Collector export, or CloudFront header behavior; those need deployment checks.
- [story] Mailpit has a protected public route. The current gateway has no Mailpit route, while the base Compose service publishes its UI only on loopback; specify the intended AWS access path and protect its API as well as its pages.

## Standards
- [story] Use [Compose’s documented merge and override rules](https://docs.docker.com/compose/how-tos/multiple-compose-files/merge/) to replace inherited settings; a successful `config` command alone does not prove local services or defaults disappeared.
- [story] Specify standard [Collector receivers, processors, exporters, and pipelines](https://opentelemetry.io/docs/collector/configuration/), including `memory_limiter`, rather than treating a Collector image and `sigv4auth` as proof that all three signals reach their destinations. The proposed AWS SSM provider is already the documented mechanism required by AD-7.

## Gaps
- [story] “Every secret and environment value” has no inventory or bounds. Name each required AWS input, distinguish deployment values from fixed container constants, and test that inherited development defaults cannot satisfy missing AWS inputs.
- [story] “Exports,” “needs basic auth,” “rejected,” and “about 3.4 GiB” need observable assertions: check each signal’s configured destination, unauthenticated Mailpit responses, missing **and incorrect** origin headers on both hosts, and an exact list of counted running services and limit units.
- [story] Move the three unowned notes into criteria: forwarded address/scheme and `nginx -t`; the telemetry-ingress decision and Collector memory limit; and `index.html`/asset cache headers with security headers retained. As written, the five criteria do not test them.

## Resolution

Sofia, 2026-10-30. The one `[decision]` point (anonymous `/otlp/v1/*` ingestion cost) is settled by the human decision above: the AWS template answers `/otlp/` with 404 and the image published from main is built with browser tracing off (criterion 6); `memory_limiter` stays in every collector pipeline (criterion 5). The SPA side needs a change in `frontend/`, which the backend builder cannot write, so it is split out as story 7.11 (owner frontend), which 7.4 waits on. `[story]` points folded:

- Inherited local behaviour: the render must start exactly the listed services, with `postgres` and `aspire-dashboard` behind a `local` profile, every replaced entry using Compose's `!override` and `!reset`, no published port but the gateway's, and no local host, `http://` public URL, `Development`, `sslmode=disable` or dev-only value; checked by `check-compose.sh` over the JSON render (criteria 1 and 2).
- Input inventory: every secret and deployment value listed with its bound in the story's Inputs; each removal must fail the render, and no `dev-only` value may survive it (criterion 1).
- Memory: an exact list of counted long-running services, a 3482 MiB ceiling, the one-shots listed apart, and a supervisor measurement of Redpanda at 512M under the e2e suite (criterion 2, Supervisor checks).
- Local checks do not prove AWS: instance-role access, collector export and CloudFront headers are moved to 7.5's written post-deploy checks (Boundaries).
- Mailpit access path: served under `/mailpit/` on the app host with Mailpit's own `MP_UI_AUTH`, which protects the API as well as the UI (checked against v1.32.0: 401 without credentials, 200 with); no host port (criterion 4).
- realip: the module parses `CloudFront-Viewer-Address` with its port itself, checked against nginx 1.31.7 (IPv4; IPv6 is disabled on both distributions); no custom port stripping (criterion 3).
- Origin header: missing and wrong values both get 403 on both hosts, and the health check sends it (criterion 3).
- Collector: named receivers, processors (`memory_limiter` first), exporters and the three pipelines, validated with `otelcol-contrib validate` (criterion 5).
- The three unowned Inputs became criteria: the AWS edge (criterion 3), the telemetry intake (criteria 5 and 6), the static cache headers with the security headers repeated (criterion 7).
