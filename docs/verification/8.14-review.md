### The two flagged test adjustments (no test weakened)

- **`CustomerPrivacyTests`, actors 4 → 3.** The old stream was raise (customer), review (`worker:seeder`,
  automation), warning (`worker:sla-sweep`) and escalate (operations). The new one is raise (customer), review
  (operations) and escalate (`worker:sla-sweep`, automation), with versions 1..3 and no gap.
  - All three actor types are still in the stream.
  - Every actor ID and trace ID is still in `forbiddenParts`, and the `worker:` automation prefix is still covered.
  - `forbiddenValues` (`customer`, `operations`, `automation`, `escalated`) are unchanged.
  - The dropped `worker:seeder` was a second automation ID that went through the same mapping (the customer view
    never carries an actor ID), so no path lost coverage. The seeder's actor stays pinned in
    `SeededDisputesTests.cs:210`.
  - Removing `nameof(SlaWarningRaised)` and `"slaWarning"` from `forbiddenParts` follows from the type no longer
    existing.
- **`SlaBatchTests` catch-up, claims ≥ 4 → ≥ 3.** The first loop over 120 disputes claims 50, 50 and 20, so 3 claims
  is the guaranteed floor. The heartbeat assertion ("at every claim: after each batch, not only once per loop") is
  still discriminating: claims 2 and 3 run inside one loop, so a heartbeat touched only once per loop fails at claim
  2. The fourth claim was the warning claim, which no longer exists. This is the bound moved to the new design, not
  loosened.
- **Other edits I checked:**
  - `SlaHeartbeatAndPrivacyTests` now counts loops as batch spans; the test raises no dispute, so each loop is one
    batch.
  - `SlaTelemetryPrivacyTests` now waits for the first batch span; three claimed disputes are fewer than 50, so the
    loop is one batch.
  - `ReadDisputeTests` still appends version 4 before version 3, so it still proves version order over row order.
  - `StoredEventReplayTests` went from a fact to a theory with one more case.
  - `PublishMappingTests` is stronger, as above.
  - The deleted tests (`DisputeSlaWarningTests`, `SlaWarningTests`, the replay warning case and the allowlist
    warning fact) test only the removed feature, as criteria 2 and 3 require.
