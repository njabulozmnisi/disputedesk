## Pre-mortem

- [story] A new policy is placed in a `.tf` file other than `main.tf`, or an action is written in a shape the two extraction rules do not recognize. CI passes while an IAM name is unchecked. Criterion 1 must either detect unsupported policy shapes and locations or narrow its “every IAM name” claim.
- [story] AWS’s live reference is unavailable or slow. With four attempts per fetch, `--max-time 30 --retry 3` can consume roughly 127 seconds **per URL**; eight sequential fetches can exceed the job’s ten-minute limit.

## Simplest design

- [story] Extract the names once from the specified files, fetch each reference once, validate the extracted names, then reuse those downloaded files for both deliberate breaks. A second fetch path or separate checker is unnecessary; this also makes the “at most once per run” requirement achievable.
- [story] Keep the small text extractor only if the story defines and enforces the supported Terraform layout. An unrestricted promise to inspect *every* policy calls for an HCL-aware approach, not two `grep` rules.

## Assumptions

- [decision] The story assumes the IAM User Guide can substitute for the programmatic reference for OIDC `:aud` and `:sub`. Its own evidence says those keys are absent from `sts.json`, while the recorded human decision requires **every** condition key to exist in the programmatic reference. Accepting that documented exception changes the decision and needs a human ruling.
- [story] The story assumes any dot-containing prefix with a standard OIDC claim is valid. Its proposed rule would also accept `unconfigured.example:aud`; the Terraform shown configures only `token.actions.githubusercontent.com`. Tie that exception to the configured provider.

## Standards

- [story] Reading HCL with line-oriented `grep` is a project-specific shortcut, not a documented Terraform parsing mechanism. Either explicitly constrain and reject unsupported layouts, or use an HCL-aware parser consistent with [Terraform configuration syntax](https://developer.hashicorp.com/terraform/language/syntax/configuration). The live-name lookup itself uses the documented [AWS service reference](https://docs.aws.amazon.com/service-authorization/latest/reference/service-reference.html).
- [decision] If the OIDC exception is approved, cite the [IAM User Guide’s OIDC federation keys](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_iam-condition-keys.html#condition-keys-wif) as its authority and state plainly that these two names are **not** verified against the programmatic reference.

## Gaps

- [story] Criterion 1 rejects an `Action` line with *no* extractable literal, but not one containing both a valid literal and an invalid or unreadable value. Specify failure when any value on a matched line cannot be checked, and test that case.
- [story] Criterion 4 needs a **whole-run bound**, not only a per-attempt timeout. Specify a retry or elapsed-time budget compatible with the ten-minute job; see [curl’s retry and timeout options](https://curl.se/docs/manpage.html).
- [story] On `main`, `publish.needs` does not include `terraform`. Thus the new job can fail while images still publish, contrary to AD-32’s “only after every other CI job passes.” Permit and require the corresponding `publish.needs` change; the current “no other job” boundary prevents it.
- [story] Criteria 1 and 5 should distinguish output from the real-tree check from output captured during the two deliberate breaks; otherwise “exactly” 13 actions and 7 keys printed conflicts with running the check three times.
