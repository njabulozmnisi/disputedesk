## Standards check

- RFC 9110: 401 / 403 / 404 / 400 used as specified; 401 carries no `WWW-Authenticate` and no redirect (AD-8, matches the story); the check order 401, 403, 400 holds.
- RFC 9457: every refusal is `application/problem+json` with the resolvable `type` and `status`; `traceId` present on 404s (the 400, 401 and 403 bodies I read had it removed by my filter, and `expectProblemShape` in the spec checks it for 400, 401 and 404); no exception text; 400 and 404 echo nothing.
- RFC 9111: `Cache-Control: no-store` on 200, 400, 401, 403 and 404.
- RFC 6265bis: the renewed session cookie keeps `path=/`, `samesite=strict`, `httponly` on every response that sets it. `Secure` is absent on the plain-HTTP local stack, as in earlier stories.
- OWASP Authorization / IDOR: another customer's ID is indistinguishable from an unknown one in status, headers and body; no ID echoed.
