# Pre-build security read: 6.2

Security (pre-build), base `ef80148`, read against 6.1's uncommitted build in `.claude/worktrees/story-6.1-r1` and the 2026-10-30 human decisions. No high, no `[decision]`. Already covered: the linking routes need the session cookie, an unlinked login (`Unlinked` policy) and the antiforgery filter. The OTP comes from the system random generator, and only its HMAC-SHA256 is stored, keyed on the challenge ID. The key is at least 32 bytes and is checked at start-up. Criterion 4 covers parallel verifies, criterion 5 two logins racing, and criterion 6 customer C. Not yet in the story: decision 1 (a correct third code links, and a login with no row is not counted) and decision 2 (link first, then re-issue).

| S1 | medium | [story] Every attempt counts the same way whatever the row holds: blank (no match, already linked, SIM swap failed), released (`OtpHmac` null), expired or active. Use one conditional increment on the login's current row (AD-12), always compute `Otp.Hmac` on the submitted code, and compare with `CryptographicOperations.FixedTimeEquals` against a fixed 32-byte dummy when `OtpHmac` is null. An expired attempt must count, otherwise a blank row, which never expires, diverges from a real one after 5 minutes. Tests: a no-match blank and an already-linked blank give the same bodies (apart from `traceId`) as a real challenge, attempt by attempt, ending in `linking-locked`. A correct code on the third attempt links. A login with no row always answers 2 and is never counted. Amend AD-12, which still says "the attempt that uses the last try ... return 409", as the decision says. (ASVS V6.6.3) |
