Fix round 1 for story 6.3 is built: all three fixes are done and the full backend suite passes (1516 of 1516). Nothing is committed. The work is in `/Users/njabulomnisi/Projects/Dojo/disputedesk/.claude/worktrees/6.3-r1`, detached at 7cba058 (`origin/main`).

**Base.** The 6.3 patch applied with no conflicts. `git apply --3way` staged it, and the fix-round changes are unstaged on top of it, so `git diff HEAD` shows the whole change. `PersonalDataRecordTests` passed, so no record needed a sealed `ToString`.

**1. Null client IP.** Tested first. The new test failed against the old code: once any other route had been hit, linking requests with no client IP had no IP limit at all. The fix gives the no-limiter partition a named constant, `NotLinkingPartition = "not linking ∅"`. It contains a non-ASCII character, so it can never equal an IP partition key or a `sub` (OpenID Connect Core says a `sub` is ASCII). I chose this over throwing on a null IP, which would answer 500 to a client connecting over a Unix socket. Connections with no IP now all share one IP partition, `""`.

I also wrote a test for the other order (a no-IP linking request first, which would put the limit on every other route). I dropped it because it cannot fail here: sign-in always reaches the limiter first, so the unlimited partition always exists by then.

**2. IP half of the audit.** `Rejected_TheSameLoginFromANewIp_AuditsAgain` fails with the `return loginIsNew;` break (only one audit entry, from IP A) and passes on the real code.

**3. Nits.**
- The `FirstRejections` comment now says a full cache compacts to 95% in the background, so a new entry is stored again once there is room.
- The logger is now created with `CreateLogger(typeof(LinkingRateLimits))`.
- `RateLimitApi` creates the `ClientAddressStartupFilter` as a local and passes it to both the service registration and the constructor.
- To let a test send a request with no IP, `ClientAddressStartupFilter.Address` (shared test infrastructure from main) is now nullable.
