## 1. Pre-mortem
- **AWS rate limits group customers together or trust a spoofed address.** Criterion 3 requires `$remote_addr`, but AD-23 requires nginx to first establish the real client address from trusted CloudFront ranges. The story does not specify or test that AWS path.
- **The inactivity dialog misbehaves under the shipped CSP.** The story records that Radix injects a blocked `<style>` element; `e2e/tests/spa-transactions.spec.ts` currently annotates the console error rather than failing on it.
- **Telemetry appears configured but never arrives.** The gateway must proxy `/otlp/`, yet the current frontend has no browser OTLP exporter; the local Aspire HTTP receiver also has a different port from its gRPC receiver (`docker-compose.yml`).

## 2. Simplest design
Build Vite assets in a pinned Node stage, copy `dist` into a pinned unprivileged nginx image, and use nginx’s documented template substitution for the two hosts. Keep app-origin security headers at nginx, API `no-store` at the Api, explicit `/assets/` 404 handling, and narrowly routed `/api/` and OTLP/HTTP proxy locations. Add one frontend CI job using the existing package scripts.

**Do not add a per-response CSP nonce solely to accommodate the dialog**: it complicates a static SPA. Resolve the known scroll-lock behavior with a concrete, tested frontend choice instead of accepting a broken behavior via a comment. Do not apply the app’s CSP to the Zitadel host; its login has its own policy.

## 3. Assumptions
- **A template works unchanged in both environments.** Local uses HTTP and Docker’s peer address; AWS terminates HTTPS at CloudFront and needs trusted-client-IP and forwarded-protocol handling (AD-23, `architecture.md:286-288`). Rendering both configurations is not proof that either routes correctly.
- **“Each header once” is already achievable by removing two Api headers.** That addresses the known `/api/` duplication (`SecurityHeaders.cs`), but auth-origin upstream headers and nginx locations with their own `add_header` need separate accounting.
- **Proxying is equivalent to browser telemetry.** AD-29 calls SPA export an assumption; `frontend/package.json` has no OpenTelemetry browser package.

## 4. Standards
- **`frame-ancestors` is a CSP directive, not an HTTP header.** Criterion 2’s wording about setting it with `add_header` must mean *inside one* `Content-Security-Policy` header; sending `frame-ancestors` separately would not enforce framing protection. See [CSP `frame-ancestors`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors).
- **Trust the proxy before using its claimed client address.** For AWS, use nginx’s [`set_real_ip_from` and `real_ip_header`](https://nginx.org/en/docs/http/ngx_http_realip_module.html) with the documented CloudFront origin-facing ranges, then forward the resulting `$remote_addr`; never accept an arbitrary incoming `X-Forwarded-For`.
- The proposed [`limit_req`](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html), [`add_header ... always` inheritance rules](https://nginx.org/en/docs/http/ngx_http_headers_module.html), and RFC 9457 problem type are established mechanisms, not custom ones.

## 5. Gaps
- Specify the **OTLP/HTTP destination and path mapping** for local Aspire and AWS collector, a numerical body cap, and which paths and methods are accepted. Test a POST reaches the receiver; a configuration read cannot establish criterion 4.
- Specify the **local and AWS rendered-config checks**, including HSTS on the intended hosts, forwarded scheme/client IP, and failure on missing template variables. `docker compose config` does not validate rendered nginx syntax.
- Make the 429 test assert **status, JSON content type, valid RFC 9457 body, exact type and absent `traceId`**, not merely “some 429s.” Test headers on proxied success and error responses as well as static files.
- Decide the Radix/CSP outcome **before build** and make its browser test fail if the chosen behavior regresses. The story currently presents two alternatives without a decision.
- State whether the security-workflow input is in scope: `.github/workflows/security.yml` currently scans only C#, despite the story’s note requesting JavaScript/TypeScript coverage.
