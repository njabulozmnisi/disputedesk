## Fix

1. **No remount on first load (review M1).** Story 3.7 criterion 6 (first Tab reaches the skip link). Key the draft provider by whether the person is signed in: `key={isSignedIn ? 'signed-in' : 'signed-out'}`, not `key={state}`. Add a routing test: a direct load of `/signed-out?reason=expired` and of an unknown path, then Tab focuses the skip link; fails with `key={state}`.
2. **A late session answer cannot undo the clean-up (verifier 1).** Criterion 1 ("nothing comes back into memory") and criterion 4 ("the in-flight request's late result restores nothing"). The clean-up also cancels the session query before it writes `anonymous`, and a session answer that lands after the clean-up (or during the ending window) is not written back as signed in. Test: hold a session request, end the session, release it as `linked`; the session stays `anonymous`.
3. **Customer data gone before the screen change finishes (verifier 2).** Criterion 1. From the moment `endSession` starts, no customer query data and no mutation remains in the cache, and nothing refetches it; only the session query may still read signed in until the navigation lands (so `SessionGate` does not race the session-ended screen). Test: hold the navigation; customer query data is already gone and no request starts.
4. **Other tabs told on a 401 at sign-out (security S1).** Criterion 3 and 4. In `useSignOut`'s 401 branch, `postToOtherTabs(queryClient, 'expired')` before returning. Test: sign-out, the token fetch answers 401, the other tab receives `expired`.
5. **One hook owns the channel (review L3).** Merge the channel handling into one `useSessionTabs(isSignedIn)` that creates and reads the channel directly; keep the WeakMap only for `postToOtherTabs`.
6. **One end per window (review L-b).** The subscriber also skips when `!isSignedIn(queryClient)`, so a second `anonymous` answer during the ending window posts nothing more.
7. **Nit (review N1).** `mutator.ts:88`: `(body as SessionResponse | undefined)?.state`.
