## 1. Pre-mortem

- The transactions screen shipped without the dispute-status badges shown in the mockup. [AD-13](docs/architecture/architecture.md) says each row carries `disputeId` and `customerStatus`, but the built [transaction response](backend/src/DisputeDesk.Contracts/Transactions/TransactionResponse.cs) and [OpenAPI contract](backend/openapi.json) contain neither; they also cannot return `alreadyDisputed`. The SPA cannot infer those facts safely.
- People lost their place on refresh or expiry. Criterion 2 sends every anonymous visit to the start page, while criterion 10 requires unknown paths to show not-found and `/signed-out?reason=expired` to remain visible. Those are conflicting routing rules without stated exceptions.
- The inactivity warning appeared at the wrong time. The server renews on **authenticated requests**, whereas criterion 9 resets the browser timer on **every API response**. Tabs have separate timers, and a response need not establish when the server renewed the session.

## 2. Simplest design

Use the generated session and transactions queries, one TanStack Router guard with explicit exceptions for `/`, `/signed-out` and unknown paths, and one shared API-error handler. Render the fields the API actually supplies; paginate with `nextCursor`, and use the documented TanStack Query retry settings. Fetch the antiforgery token after sign-in and place it in both unsafe-request headers and the logout form. Keep one warning timer for presentation, never as the authority for session validity.

Do **not** create a frontend dispute lookup or guess an `alreadyDisputed` state to reproduce the mockup. Either deliver the missing row contract before this story or explicitly defer those badge states and the “every state from the mockups” claim.

## 3. Assumptions

- **Contract readiness:** [AD-13](docs/architecture/architecture.md) assumes dispute metadata on transaction rows; [story 2.3](docs/tickets/epic-2-transactions/tickets/story-2.3-linked-customer-lists-their-own-transactions.md) specified only `notEligible` and `outsideWindow`, which is what the current API implements. This is a dependency or scope decision, not a frontend implementation detail.
- **No browser token:** Criterion 3 is true for SPA code and storage, but [AD-7](docs/architecture/architecture.md) expressly sends an ID token through the browser in the logout redirect. “No token in the browser” needs that exception stated precisely.
- **Warning timing:** A response-based clock is assumed to represent server expiry, but neither the [session response](backend/src/DisputeDesk.Contracts/Bff/SessionResponse.cs) nor OpenAPI exposes an expiry instant.

## 4. Standards

- Routing on the *last segment* of a Problem Details `type` is a repository convention, not the identity rule in [RFC 9457 §3.1.1](https://www.rfc-editor.org/rfc/rfc9457.html#section-3.1.1). Compare known full type URIs, or explicitly retain and test the slug convention; never fetch the URI.
- A browser timer must not become a session-expiry mechanism. [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#idle-timeout) requires server-side idle enforcement; the warning and extension should meet [WCAG 2.2 Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html). AD-7 has server enforcement, but criterion 9 does not specify how its warning remains accurate across tabs or delayed requests.

## 5. Gaps

- Resolve the routing precedence for an unknown path, an anonymous visit to `/signed-out`, and a signed-in visit to `/`. Specify what happens when the initial session request fails rather than treating failure as anonymous.
- Define how the logout form obtains a fresh `__RequestVerificationToken`, what it shows if that request fails, and whether “Stay signed in” closes the dialog **only after** session renewal succeeds.
- Specify the observable test for “every API response restarts the timer”; as written it includes anonymous and failed responses that do not renew an authenticated session. Also test expiry during Load more and simultaneous tabs.
- Criterion 6 cannot test the mockup’s already-disputed rows against the current contract. Decide whether the backend contract changes first or those states leave this story.
