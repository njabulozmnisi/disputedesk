# Pre-build security read: 5.3

Security (pre-build), base `ef80148`. No high, no `[decision]`. Already covered: `OwnershipRulesTests` already allows `IgnoreQueryFilters` only in `Operations/` and `Sla/`. The warning is never published (the AD-14 mapping sends it nowhere) and is hidden from customers (3.8's allowlist). Criterion 4 asserts the customer sees `theBank` and the outbox carries `actorType` `automation`. Not ready to build until the dated lead-time `Decision:` line is in the Notes, though the lead time itself has no security effect.

| # | Sev | Finding |
|---|---|---|
| S1 | low | [story] The automation actor is defined once, as a constant in `Application/Sla/` (`new Actor(ActorType.Automation, "worker:sla-sweep")`). A source-rule test fails on `ActorType.Automation` outside `Sla/` and the 5.4 seeder, so no HTTP path can record an automation actor. Criterion 1 asserts `ActorType` and `ActorId` on the stored event. (ASVS V16.2.1; AD-14a) |
| S2 | low | [story] Exclusion between Workers: the sweep takes no leader lock and never uses the relay's advisory-lock connection. For each batch, the claim (`FOR UPDATE SKIP LOCKED`), the replay and every escalation commit run in one transaction on one connection, so the row locks hold until commit. EF Core's automatic savepoints mean one clash does not abort the batch (EF Core, *Transactions*: savepoints). Criterion 2's two sweeps run concurrently with overlapping transactions, not one after the other. A test races a sweep against a 5.2 operations escalate on one dispute and gets exactly one `DisputeEscalated` (AD-15 version index). (ASVS V2.3) |
| S3 | low | [story] No customer data in telemetry. The sweep's logs, the `disputedesk.sla_sweep.batch` span and the `disputedesk.sla.escalations` metric carry counts and at most dispute IDs, never `CustomerId`, `AccountRef`, `TransactionId` or the snapshot. Exceptions are logged by type only. Extend AD-20's telemetry check to a Worker sweep run: the captured logs and spans hold no seeded customer ID or account reference. (ASVS V16.2.5; OWASP Logging Cheat Sheet) |
| S4 | low | [story] Raw SQL: each claim is one named, parameterised Infrastructure method (`@now` and the lead time as parameters, never formatted into the SQL). The bypass names only the filter, `IgnoreQueryFilters(["Ownership"])`, never the form with no arguments that drops every filter. The architecture test's regex does not check the name. (ASVS V1.2.4; AD-2, AD-11) |
