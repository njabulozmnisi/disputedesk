### Standards

- RFC 9110 and RFC 9457: 429 is `application/problem+json` with `Retry-After: 900` (delay-seconds); 409 and 422 also problem JSON. No deviation seen.
- Not exercised on the stack (component and unit tests only): the HTTP-date form of `Retry-After` and the elapsed wait, 403 `already-linked` from another tab, the SIM-swap lock (customer C: no challenge is sent, so verify answers 422), a 5xx on the screens. The verifier notes `retryAfter.ts` accepts only the IMF-fixdate form of HTTP-date, while RFC 9110 section 5.6.7 requires recipients to accept all three (a standards finding, no effect on the criteria; the gateway and Api send delay-seconds).
- Playwright note for the next author: a button with `aria-disabled` is not "disabled" for Playwright, so a click on it needs `force: true` or it waits for ever. This is why the screens use `aria-disabled` (the button keeps focus) and the spec forces the press.
