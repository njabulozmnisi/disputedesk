**Fixes**
1. **Uppercase GUID.**
   - `frontend/src/app/router.tsx`: `params.parse` now returns `disputeId.toLowerCase()`, so every query key and request path for the dispute has one form. The URL in the address bar is left as typed.
   - The new test serves the dispute case-insensitively and returns the lowercase `disputeId`, as the real API does. It asserts the page shows Withdrawn after the withdraw.
   - A sibling test asserts the GET goes to the lowercase path.
   - Before the fix, the cache-key test failed with "Unable to find Withdrawn" and the GET-path test failed because the request used the uppercase path.
2. **Failed refetch after a conflict.**
   - `frontend/src/features/disputes/detail/DisputeDetailScreen.tsx`: the screen no longer drops `query.data` when `query.isError` is true. The loaded card, and the withdraw dialog it owns, stay mounted. The failure notice with Try again renders above the card as a sibling at a fixed position.
   - A dispute that was never loaded still shows the failure card. A 404 on refetch, or on the withdraw, still gives the not-found screen.
   - Try again focuses the heading on success, as before.
   - The old test "checks the error before the data: a failed refetch leaves no stale detail" asserted the opposite behaviour, so I replaced it with one that asserts the loaded card stays.
   - Before the fix, four new tests failed for the right reason (the dialog and notice unmounted, or the heading was lost). They cover a failed refetch on its own and a conflict with `resolved`, with an open status, and with `withdrawn`, each followed by a failing GET.
   - Two further tests pass both before and after the fix: a 404 on a plain refetch, and a conflict followed by a 404 GET.
3. **Axe coverage** (`DisputeDetailScreen.test.tsx`).
   - The old "loading or failing" test is split into two. Loading runs axe while the response is gated, with `aria-busy` present. Failure runs axe on the failure card.
   - I added axe on the loaded detail with a failed refetch, and axe in the 501-character note-error test.
