## 1. Pre-mortem
- [story] A month later, a fixture dispute is silently skipped because the bypass query finds a row owned by another customer. The new predicate is meant to prevent that, but the proposed Supervisor check would not prove it: the query also matches `accountRef`, and the database uniquely indexes `(AccountRef, TransactionId)`.

## 2. Simplest design
- [story] In both seeding delegates, use the migrating context to check each planned dispute with `IgnoreQueryFilters(["Ownership"])` and predicates for customer ID, account reference and transaction ID. Keep one `SaveChanges` per new dispute stream; remove `ContextFor` and its uses. Add `Seeding/` to the existing folder rule. No new context factory, DI scope or query abstraction is needed.

## 3. Assumptions
- [decision] D6 authorizes a third bypass, but [PRD NFR-SEC-6](docs/prd/prd.md) and [initiative R17](docs/initiative-disputedesk.md) still say **only** Operations and Worker bypass the filter. Align those requirements with the already-recorded decision; changing AD-11 and AD-30 alone leaves contradictory rules.
- [story] The story assumes seeding is always “inside the migration’s transaction.” `Seeder.cs` explicitly distinguishes the case where pending migrations have already committed. Preserve its one-save-per-stream and retry behavior, but qualify the transaction claim.

## 4. Standards
- [story] No invented mechanism is needed. The proposed named bypass and seeding hooks are documented EF Core mechanisms: [global query filters](https://learn.microsoft.com/ef/core/querying/filters) and [data seeding](https://learn.microsoft.com/ef/core/modeling/data-seeding).

## 5. Gaps
- [story] Replace the predicate-drop Supervisor check. Giving B a dispute with A’s **transaction ID alone** does not create a match when account references differ; giving both the same indexed tuple prevents B’s insert even with the correct predicate. Instead, test the predicate against an existing wrong-customer row and assert the seed **fails rather than silently skips it**, for both sync and async paths.
- [story] Criterion 4 says the existing tests pass unchanged and a second start seeds nothing. `SeededLinksTests.Seeder_FreshStartThenRunAgain_LinksAAndBOnceAndNotCOrD` already checks the latter; name it in the criterion. Allow a new focused predicate test while keeping existing tests unchanged.
