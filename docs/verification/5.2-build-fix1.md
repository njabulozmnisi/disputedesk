**Fixes**
1. **Two-clash test (medium).** The second armed clash is now `DisputeEscalated` from Escalated to Escalated at version 4, with the row left at Escalated. Escalated still allows resolve, so a third replay-and-decide would commit and answer 200. The test now expects 409 `disputeStatus: escalated`, a stream ending at version 4, the row at Escalated/4 and one `Rejected` row. I replaced the false comment. I confirmed the test fails against a handler that retries a third time ("Expected: Conflict, Actual: OK"), then removed that retry.
2. **Sealed `ToString` (F3).** `OperationsDisputeResponse` and `OperationsTimelineEntryResponse` now print only their type name, in a sealed override. A new test, `OperationsResponsePrivacyTests`, sets every field (marker strings, the snapshot, the resolve note) and checks for an exact type-name match and `IsFinal`.
3. **`AcceptsMetadata` comment.** The comment in `OperationsEndpoints.cs` now points to AD-8 and names the aspnetcore source (`src/Http/Routing/src/Matching/AcceptsMatcherPolicy.cs`, release/10.0) and the two pinning tests. Both reports said this behaviour was unverified. I read the source: an empty `ContentTypes` list matches any content type and never asks for a 415 endpoint. The AD-8 entry itself is still yours.
6. **One stamping style.** `Dispute.Withdraw` now uses `Stamped(...)` like the three new methods.
7. **Metric label.** `RecordOperationsAction` takes the label from the endpoint (`"startReview"`, `"escalate"`, `"resolve"`), the way `RecordWithdrawn` hard-codes `"withdraw"`. The `WireName` switch is gone.
