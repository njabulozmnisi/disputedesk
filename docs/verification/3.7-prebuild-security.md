# Pre-build security read: 3.7

Security (pre-build), base `b009f12`, with 3.4's withdraw contract (`story-3.4-r1`). No high, no `[decision]` if the toast uses the existing live region (S3).

Already covered:
- `customFetch` adds `X-XSRF-TOKEN` and same-origin credentials on unsafe methods.
- 403 `linking-required` and 401 are handled once, in the QueryClient caches.
- The API answers 404 for another customer's dispute and for one that does not exist.
- `Referrer-Policy: strict-origin-when-cross-origin` and `connect-src 'self'` keep the `/disputes/<id>` path on the origin.
- Source scans already forbid `localStorage`, `sessionStorage`, `document.cookie`, `indexedDB` (`app/noToken.test.tsx`) and `dangerouslySetInnerHTML`, `<style>` and `style=` (`RaiseScreen.test.tsx:398-415`).

| S1 | medium | [story] Client-side path traversal through the route ID. TanStack Router decodes path params (`router-core/dist/esm/new-process-route-tree.js:333`, `decodeURIComponent`). The generated client puts `disputeId` into the URL unencoded (`generated/disputedesk.ts:683`). So `/disputes/..%2F..%2Fbff%2Fsession%3F` makes the detail GET hit `/api/v1/bff/session?`. The withdraw POST, which carries `X-XSRF-TOKEN`, would hit `/api/v1/<chosen path>?/withdraw`. Fix: the route's `params.parse` (TanStack Router path params, checked against 1.170.46) accepts only the canonical 8-4-4-4-12 hex GUID and throws `notFound()` before any query runs. The detail and withdraw hooks take only the parsed value. Test with `/disputes/abc`, `/disputes/..%2Fx%3Fy%23z`, `/disputes/<guid>%2F..` and a braced GUID: each shows the not-found screen, and MSW records no request under `/api/v1/disputes` (ASVS 5.0 V1.2.2, V2.2.1) |
