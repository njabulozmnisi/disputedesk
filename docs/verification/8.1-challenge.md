## 1. Pre-mortem

- [story] A bad brand asset passes CI because the upload check runs only when Zitadel has no asset URL. On an already-provisioned stack, `provision.sh` skips the upload; removing the CI step also removes its checks that `tokens.css` names both wordmarks and loads neither.
- [story] `push-and-watch.sh` exceeds its 1,800-second limit: the proposed deadline bounds discovery of run IDs, but `gh run watch` can keep waiting after an ID is found. Watching CI and Security sequentially makes this more likely.
- [story] A lane silently changes behavior because the generated runner currently embeds the locally selected `LANE_AGENT`; copying a fixed runner with only the story ID does not convey that choice to the remote host.

## 2. Simplest design

- [story] Install the two pinned linters in `floor-guard`; keep the label generator limited to the known, repo-owned declaration shape and retain the exact-values check. Reuse `security-local.sh`, use a committed lane runner with explicit story ID **and agent** arguments, and use `jq` locally with errors propagated. Replace status polling with `gh run watch`, but retain one enforceable overall deadline. Do not retain the 11 YAML mutation cases.
- [story] Remove only the brand checks actually covered by an attempted upload. Keep a small CI check for the wordmark references and for assets that provisioning may skip, or explicitly narrow the earlier story’s promised coverage.

## 3. Assumptions

- [story] “The upload is the one check” assumes an upload occurs for changed files. `provision.sh` checks URL presence, not file contents, and its own `shortcut:` says changed logos or fonts need `down -v`.
- [story] “Plain lookup” assumes comments cannot impersonate declarations. `tokens.css` has inline and multiline comments; deleting the comment stripper without defining an accepted line shape can change which value is selected.
- [story] `decisions: settled` assumes a field in a story proves a **human** settled every `[decision]` point. The current proposed check establishes only that the text was entered, not who decided or which point it covers.

## 4. Standards

- [story] `actionlint`, ShellCheck, `gh run watch --exit-status`, and `jq` are documented tools, not invented mechanisms ([actionlint](https://github.com/rhysd/actionlint), [ShellCheck](https://www.shellcheck.net/), [gh run watch](https://cli.github.com/manual/gh_run_watch), [jq](https://jqlang.org/manual/)).
- [story] A shell lookup must not claim to parse arbitrary CSS. Either bound input to the literal declaration form this repo supports, or use the [CSS Syntax declaration rules](https://www.w3.org/TR/css-syntax-3/#consume-a-declaration/) with a CSS parser. The former is simpler here.
- [story] The front-matter field is a repo-specific readiness convention, not a standard mechanism for human approval. State that limit and retain the recorded human disposition required by `AGENTS.md`.

## 5. Gaps

- [story] Criterion 5 needs cases for a run that fails **before** watch starts, a `gh` failure during watch, and a run that never finishes; specify how each preserves exit code 1 or 2 and the overall timeout.
- [story] Criterion 7 needs a test that `decisions: settled` occurs **inside front matter**, not in the body, plus missing, duplicate, and other-value cases. Specify whether one marker settles multiple `[decision]` points.
- [story] Criterion 8 needs the `LANE_AGENT` transfer specified, malformed or missing JSON to fail rather than print a success-shaped value, and a check that the copied runner is executable. The stated `bash -n` check cannot validate the new `.zsh` runner; use `zsh -n` for it.
- [story] Criterion 3 no longer tests “one declaration per block” after removing the duplicate count. Either remove that input bound explicitly or retain a focused duplicate test; the exact-values step alone cannot prove uniqueness.
