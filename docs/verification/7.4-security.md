# 7.4 security review

Findings: 4 low, 1 informational; no medium or high. Every pre-build point (S7.4-1 to S7.4-10) is met in the diff. The builder's flags were judged and accepted: the non-constant-time origin-verify compare (AWS's documented shared-secret pattern; WAF or an HTTPS origin is already on the production path), the value in `Config.Env` and the rendered config (the same exposure as every `.env` secret; the health check shows only the variable name), SSM credentials resolved before options validation (no key is created before `ValidateOnStart` stops the start), and the anchored KMS key ID or ARN bound.

- **F1 low.** `otel/opentelemetry-collector-contrib:0.164.0` (pinned by digest, latest stable) carries HIGH CVE-2026-116587 in go-jose v4.1.5 (crafted-JWK denial of service). Not reachable: no JWT or OIDC extension, private network only, no published port. No fixed release exists. Disposition: production path P58; upgrade once a release ships go-jose 4.1.6 or later.
- **F2 low (7.3).** `security.yml` scanned the `api` and `worker` targets while P57 publishes `api-local` and `worker-local`. Disposition: 7.3's story now scans the published targets.
- **F3 low.** In AWS, `ForwardedHeaders__TrustedNetwork` trusts the whole /24, so internet-facing containers (Zitadel, zitadel-login, Mailpit) could call `api:8080` with a forged `X-Forwarded-For` and get past the per-IP linking limits (ASVS 5.0 V4, V13). Disposition: fix round: pin the gateway's address and trust only that /32 (Microsoft Learn, *Configure ASP.NET Core to work with proxy servers and load balancers*).
- **F4 low.** The Api accepts any non-blank `DataProtection:KmsKeyId`, aliases included; only `input-bounds.sh` rejects `alias/` at deploy. Disposition: fix round: one more `.Validate`.
- **Informational.** The collector's OTLP receiver has no authentication on the private network; bounded by `memory_limiter` and no host port.

Package verification: `Amazon.AspNetCore.DataProtection.SSM` 4.0.3, Amazon Web Services (owner `awsdotnet`, reserved prefix), 19.34M downloads, github.com/aws/aws-ssm-data-protection-provider-for-aspnet, latest stable, no known vulnerabilities, pinned. Collector tag 0.164.0 resolves to the pinned manifest digest.

Scanners in the tree: secret scan clean (whole change); `dotnet list package --vulnerable --include-transitive` none; `trivy fs` HIGH/CRITICAL clean; `trivy image` on the collector 1 HIGH (F1).
