Checked in the npm registry on 2026-10-30 by reading the published tarballs, without installing them:
- OpenTelemetry JS 3.0 / 0.300 shipped on 2026-10-20.
- `@opentelemetry/sdk-trace` 3.0.0 exports `TracerProvider`, `BatchSpanProcessor`, `StackContextManager` and `InMemorySpanExporter`. It has no `WebTracerProvider` and no `register()`.
- `@opentelemetry/sdk-trace-web` and `sdk-trace-base` 2.12.0 are deprecated with "Use @opentelemetry/sdk-trace package".
- `FetchInstrumentation` in `@opentelemetry/instrumentation-fetch` 0.300.0 is marked `@deprecated`, pointing to `@opentelemetry/browser-instrumentation` 0.9.0. That package says of itself: "experimental … may include breaking changes".
- The `context-zone-peer-dep` 3.0.0 README says: "`ZoneContextManager` does not work with JS code targeting ES2017+".
- `otlp-transformer` 0.300.0 no longer depends on protobufjs.
- The browser OTLP fetch transport sends with the unpatched `fetch.__original` under `suppressTracing`, so exports are never traced.

CSP: `connect-src 'self'` (`infra/nginx/templates/security-headers.conf.template:5`) covers `/otlp/v1/traces`. The gateway accepts only POST there, caps the body at 1 MB, strips `Cookie` and `Authorization`, and applies the coarse limit (`nginx.conf.template:92-110`). No CSP change is needed.
