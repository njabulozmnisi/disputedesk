## Pre-mortem

- [story] A session failure leaves a guarded route stuck on its error screen: `ensureQueryData` throws in `beforeLoad`, but the story does not say how “Try again” resets that route error and reruns the guard.
- [story] An oversized `returnUrl` now reaches login and receives a 400 instead of a sign-in redirect. The proposed search validation retains every string, while the BFF’s `[MaxLength(2048)]` rejects longer values.

## Simplest design

- [story] Put the three state checks on pathless `beforeLoad` routes, use the existing generated session query options, and keep the public routes outside those layouts. Use the router’s route-error retry mechanism; do not introduce another session cache or redirect rule.
- [story] Use the existing `ErrorSummary`, `Field`, React Hook Form and zod patterns for withdraw. Keep its current trimmed request body, pending-dialog lock and 409 handling; replacing state is worthwhile only where those behaviors remain explicit.

## Assumptions

- [story] The router can receive a query client at construction without changing initialization. It currently cannot: `main.tsx` creates the router first, then `createQueryClient(router)`, because the client’s error handlers navigate through that router. Specify the small bootstrap change needed to break this dependency.
- [story] Moving the cached-row check to `beforeLoad` preserves a row for the whole raise flow. `RaiseLayout` currently captures it once in state so cache collection does not eject a customer mid-flow; specify how the admitted row remains stable across form/review navigation.

## Standards

- [story] No invented mechanism is needed for route guards or retries. Use TanStack Router’s documented [authenticated-route `beforeLoad` and redirects](https://tanstack.com/router/latest/docs/framework/react/guide/authenticated-routes) and [router-context pattern](https://tanstack.com/router/latest/docs/framework/react/guide/router-context); identify how the error component retries the failed guard.
- [story] The proposed `z.config` call in `main.tsx` does not cover tests that import schemas directly without running `main.tsx`. Keep the CSP/jitless guarantee testable in those entry points, rather than relying on application startup alone.

## Gaps

- [story] Criterion 1 needs a test for a failed session request followed by “Try again,” including the retry count and the eventual admitted or redirected screen. It also needs a raise form-to-review test after the transaction-list cache entry disappears.
- [story] Criterion 5 needs an explicit expected outcome for a string longer than 2048 characters; “every string reaches the BFF” and “customer behavior is unchanged” cannot both hold with the current BFF validation. The existing frontend test expects the oversized value to be dropped.
