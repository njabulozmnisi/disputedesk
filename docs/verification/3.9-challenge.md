## Pre-mortem

- [story] History pages become slow as disputes accumulate: the story explicitly omits an index for the ownership filter and descending sort. Keep the shortcut only with a measurable threshold for adding the named index.
- [story] A full final page incorrectly advertises another page if the query fetches only `limit` rows. Fetch `limit + 1` to determine `nextCursor`.

## Simplest design

- [story] Add one cookie-authorized list endpoint. Query the ownership-filtered `Disputes` read model with a SQL keyset predicate, order by `CreatedAtUtc` and `Id` descending, take `limit + 1`, and map only the requested rows through the existing customer-view rules. The cursor contains only the last returned ordering pair; no signature, replay, stored-event join, or new pagination abstraction is needed.

## Assumptions

- [story] Paging is not a frozen snapshot: disputes added between requests may fall before an existing cursor and not appear in that traversal. AD-5 specifies keyset paging but no snapshot guarantee; state this expectation.
- [story] PostgreSQL UUID order matches the comparison used by the chosen EF/Npgsql translation. The story calls for a generated-SQL check; the tied-ID integration test must also execute against PostgreSQL.

## Standards

- [story] The proposed keyset predicate and opaque cursor follow [EF Core’s keyset-pagination guidance](https://learn.microsoft.com/en-us/ef/core/querying/pagination) and [RFC 4648 §5](https://www.rfc-editor.org/rfc/rfc4648#section-5). No invented mechanism is necessary. A provider-specific GUID or row comparison is acceptable only after its SQL translation and actual ordering are verified.

## Gaps

- [decision] Criterion 6 asks a seven-fractional-digit transaction date to remain the **same string** in the raise response and database-backed reads. The raise response is constructed before saving, while the snapshot is stored as PostgreSQL `timestamptz`, which retains microseconds, not .NET’s seventh fractional digit ([PostgreSQL date/time types](https://www.postgresql.org/docs/current/datatype-datetime.html)). Decide whether the contract canonicalizes that date to stored precision before the 201 response, or the architecture changes how full precision is stored; the current criterion cannot pass for a nonzero seventh digit.
- [story] Criterion 2 needs explicit cases for a negative or overflowing `limit` and a cursor whose decoded timestamp or GUID is malformed. These complete the stated input bounds and ensure malformed input gets 400 rather than an exception.
