### Order independence (L3)

Order independence rests on data scoping, not on luck of ordering:

- Each journey uses its own dispute or its own login: UJ-1 customer D (TXN-D-0030, newly signed-up user), UJ-2 A's `TXN-A-0022`, UJ-5a B's dispute read by A, UJ-5b A's resolved `TXN-A-0015`, UJ-5d login C.
- Every count assertion compares before and after inside the one test, filtered by that test's dispute ID (or login), never a table total.
- `workers: 1` in `playwright.config.ts`, so journeys never overlap.
- Audit writers are request-driven: a row appears only when the test's own request is refused, so no background writer can add a row to a dispute another journey is watching.
