# 6.4 pre-build security (status: findings, all low)

What already holds:
- No value goes into the URL or storage.
- `returnUrlAfterSignIn` keeps `/link` and `/link/otp` as they are, and those paths hold no value.
- The mutator sends `X-XSRF-TOKEN` on unsafe methods.
- Mutations use `retry: false`.
- The 202 is handled the same way in every case, and the locked screen is the same for a SIM-swap failure.
- `attemptsRemaining` is read only from `otp-incorrect`.
- No `console.*`, devtools or storage calls exist in `frontend/src`.

- **S6.4-1 low [story] The mutation cache keeps the submitted values.**
  - Problem: TanStack Query's `MutationCache` keeps each mutation's `state.variables` (`{ data: { idNumber, accountNumber } }` and `{ data: { code } }`) in memory until `gcTime` runs out (5 minutes by default) after the screen unmounts. That breaks the Inputs line "no … query cache".
  - Fix: set `gcTime: 0` on the start and verify mutations.
  - Standard: TanStack Query `useMutation` `gcTime`; ASVS 5.0 V14.3 (client-side data protection).
  - Builder must test: after a 202 has moved the SPA to `/link/otp`, and again after a 204, the serialised `queryClient.getMutationCache().getAll()` contains no ID number, account number or code.

- **S6.4-2 low [story] Browser spellcheck can send field contents to a vendor.**
  - Problem: Chrome's Enhanced Spell Check and Edge's Editor send text-field contents to their vendors, and `autocomplete="off"` does not stop that.
  - Fix: add `spellcheck="false"` to `idNumber`, `accountNumber` and `code`.
  - Standard: WHATWG HTML `spellcheck` attribute; ASVS 5.0 V14.2 (no sensitive data sent to third parties).
  - Builder must test: a component test asserts the attribute on all three inputs.

- **S6.4-3 low [story] Automatic fetch spans already cover the linking calls.**
  - Problem: story 3.11's `FetchInstrumentation` makes a span for every same-origin fetch, including `/api/v1/linking/start` and `/verify`. The span carries the sanitised URL, the method and the status, and no body (`measureRequestSize: false`). The boundary "no browser spans for linking" therefore means no new span and no new attribute.
  - Standard: AD-20; ASVS 5.0 V16.2.
  - Builder must test: with `startTracing` and an in-memory span processor (as `startTracing.test.ts` does), a start and a verify produce no span attribute containing the ID number, the account number or the code.

- **S6.4-4 low [story] Values are never echoed back.**
  - The error-summary links point at field IDs (`#idNumber`), never at values.
  - Builder must test: criterion 1's history test also checks `location.hash`. In every error state (client validation, a server 400, 422, 409, 429), the rendered text does not contain the typed value.

## Resolution

Sofia, 2026-10-30. Every point was `[story]`; all are folded into the story.

- S6.4-1: both mutations set `gcTime: 0`; criterion 1 tests the serialised mutation cache after the 202 and after the 204 (Inputs; criterion 1).
- S6.4-2: `spellcheck="false"` on `idNumber`, `accountNumber` and `code`, asserted by a test (Inputs; criterion 1).
- S6.4-3: the boundary now reads "no new span or span attribute"; criterion 1 tests with an in-memory span processor that no span attribute holds a submitted value (Boundaries; criterion 1).
- S6.4-4: criterion 1 checks `location.hash`; criterion 8 checks that no error state's text holds a typed value and that summary links point at field ids.
