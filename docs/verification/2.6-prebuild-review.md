# Pre-build review: 2.6

Reviewer (pre-build), base `8134305`. Verdict: changes. Every point is `[story]`; none is `[decision]`. I did not read `2.6-challenge.md`. I checked the facts below against the Zitadel source and docs at tag `v4.20.0`, the version pinned in `docker-compose.yml`:

- **Label policy API.** The instance label policy is set through the Admin API v1: `GetPreviewLabelPolicy` (`GET /admin/v1/policies/label/_preview`), `UpdateLabelPolicy` (`PUT /admin/v1/policies/label`, which updates the preview) and `ActivateLabelPolicy` (`POST /admin/v1/policies/label/_activate`). None of them is deprecated. The v2 `SettingsService` only has `GetBrandingSettings`, so it cannot write.
- **Field limits.** Each colour field allows at most 50 characters. `themeMode` takes `THEME_MODE_AUTO`, `THEME_MODE_DARK` or `THEME_MODE_LIGHT`.
- **Asset uploads.** Logo, logo dark and font go to `POST /assets/v1/instance/policy/label/{logo,logo/dark,font}` as multipart with a form field called `file`. Zitadel works out the file type from the bytes, not from the request header. Font accepts `font/*` or `application/octet-stream`; logo accepts `image/*`. Each file can be at most 512 KiB (`internal/api/assets/login_policy.go`, `asset.go`). So the WOFF2 file (13 KiB, detected as `font/woff2`) is accepted.
- **No-change update fails.** Sending an update that changes nothing returns `Errors.Instance.LabelPolicy.NotChanged`, a failed-precondition error (`internal/command/instance_policy_label.go:44`), which comes back as HTTP 400.
- **What Login v2 uses.** It applies the four colours, light and dark; `logoUrl` for light and dark; `fontUrl` as a single `@font-face` with no weight; and `themeMode`. It never reads `iconUrl`. It caches branding settings for 1 hour (`apps/login/src/lib/zitadel.ts:57`).
