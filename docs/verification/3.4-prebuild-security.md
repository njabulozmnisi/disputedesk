# Pre-build security read: 3.4

Security (pre-build), base `8134305`. No high, no `[decision]`. Already covered by the code 3.4 builds on:
- **Ownership:** `DisputeReplay` reads `StoredEventRow` through the named `Ownership` filter, which reaches stored events through their dispute (AD-11). Another customer's dispute and an unknown ID take one code path.
- **Check order:** 401, 403 and 400, through the `Linked` policy and the customer group's `AntiforgeryFilter`. Withdraw inherits both, and a CSRF-less request gets 400 before any lookup, so it cannot reveal ownership.
- **Caching:** `Cache-Control: no-store` on everything under `/api`.
- **Published event:** `DisputeWithdrawn` maps to `status-changed.v1` with exact data keys and no note (`PublishMappingTests`).
- **Stored events:** `StoredEvent.ToString` is sealed; both tables are insert-only (guard plus `AuditLogRulesTests`).
- **Version clash:** mapped to `Conflict` in `UniqueViolations`.
- **Sensitive logging:** `EnableSensitiveDataLogging` is off (`DatabaseLoggingTests`).

## Resolution

2026-10-30, Sofia (refine). All points folded into story 3.4; criteria numbers are the refined story's.

- S1: nothing written on A's withdraw of B's open dispute, and the identical 404 with a 501-unit note: criterion 4.
- S2: `StoredEventPrivacyTests` extended to a withdraw and its 404 and 409 refusals: criterion 7. Labels follow AD-20 (`action`, `actor_type`; the histogram has none), where this read wrote `actorType`; the architecture wins.
- S3: one choice fixed, no filter (the pre-build review's suggestion), so no blanket filter and no filter test; `Include Error Detail` stays off as a Boundary, with no new test. The alert exclusion goes to `docs/production-path.md` through story 7.6's Notes.
- S4: every column checked, `DisputeId` per response, equal rows for B's dispute and the unknown ID: criterion 8.
- S5: every non-audited response named with the suggested rule (validation and dependency errors are not audited): criterion 8.
- S6: over-recording on take-over accepted, commits not merged, audit save after the lost-race clear: Boundaries.
- S7: no `Idempotency-Key` (criterion 1); two withdraws in a row leave one `DisputeWithdrawn` and one outbox row (criterion 3), and the second writes one `Rejected` row (criterion 8).
- S8: the source rule covers both forms with sample-line theories: criterion 8.
- S9: an Input for `docs/production-path.md` in story 7.6's Notes (the file does not exist yet; 7.6 writes it); Boundaries says no limiter is added here.
- S10: every input with its bounds and results: criterion 2. A non-JSON content type gets 415 `validation`, as the raise does in code today.
