## Findings

- **F1 (medium, fails criterion 4's axe requirement and NFR-CODE-6): `definition-list` violation on screen 4b.** Axe (wcag2a, 2aa, 21a, 21aa, 22aa) on "Review your dispute": `<dl>` elements must only directly contain `<dt>`/`<dd>` groups, `<script>`, `<template>` or `<div>` elements; the `<div>` holding the Change link (`ReviewScreen.tsx`, the `<div className="py-3"><Link … Change>` inside the `<dl>`) is not a dt/dd group (WCAG 2.2 SC 1.3.1). Fix: move the Change link outside the `<dl>`.
- **F2 (medium, fails criterion 4): the error summary does not take focus when the field's error is already showing.** A note over 1,000 characters shows its error on blur. Pressing Continue then increments the summary, which appears, but focus ends on the Note textarea (observed: `TEXTAREA#note`), not the summary. Cause is likely React Hook Form's `shouldFocusError` moving focus to the first invalid field after `onInvalid`, after the summary's focus effect ran. When the summary and the first error appear together (empty reason, empty expected amount) the summary does take focus, which is why the unit tests pass. Fix: set `shouldFocusError: false` on `useForm` (the summary links already move focus to fields) or focus the summary after RHF's focus.
- **F3 (low, usability): the first press on Continue can be lost to the blur validation.** With a too-long note, the press blurs the textarea, the field error appears, the layout shifts and the pointer-up lands off the button: no click, no summary (reproduced once by hand, and in the e2e walk; intermittent there). A second press works. Validate-on-blur is in the story (criterion 2), so this is a design note: reserving space for the error line, or validating on `mousedown` ordering, avoids it.
- **Observations, no action:** (a) Change returns the expected amount exactly as typed, spaces included; the request is trimmed. (b) A 401 stops at the request-token fetch, so criterion 8's "401 on 4b" reaches the session-ended screen before any POST. (c) The refusals write no audit row, as in 3.8.

## Standards check

- RFC 9110: 201 with `Location`; 400, 401, 404, 409, 422 each used for its meaning; the replay returns the stored 201.
- RFC 9457: refusal bodies carry the resolvable `type`, `status` and `traceId`; the SPA shows only its own copy and the reference.
- RFC 9651: `Idempotency-Key` sent as a quoted string (`"<uuid>"`) on every attempt (draft-ietf-httpapi-idempotency-key-header).
- OWASP ASVS V3.5.1 / CSRF: `X-XSRF-TOKEN` on every POST, including the five in-progress resends.
- WCAG 2.2: SC 1.3.1 failed on 4b (F1); SC 3.3.1 error identification met; SC 4.1.3 met (`role="alert"` notices and the polite region); focus handling failed in one path (F2).
- CSP: the gateway's headers unchanged; the console showed no error beyond the accepted Radix style notice.
