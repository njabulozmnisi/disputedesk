## What holds

- **The required check always reports.** The new job has no job-level `if` and no `needs`, so it always runs. `ci-gates.sh` (:18-30) rejects a job-level `if`/`needs` and requires the job in `ci-passed`'s `needs`.
  - A job whose suite steps are skipped by a step-level `if` still ends `success`. `ci-passed` (:533) passes only on `success`, so a skipped *job* would fail the gate rather than slip through.
  - A workflow-level `on.paths` filter would leave `ci-passed` pending forever. ad-012 rejects it for that reason (Options rejected).
  - The spec's design avoids all three traps. No marketplace action is added; ad-012 also rejects `dorny/paths-filter`.
- **Skipping the suite on `push` to main is sound.** The ruleset requires an up-to-date branch (`strict_required_status_checks_policy: true`) and allows only squash merges. So the squash commit's tree is the tree the pull request's merge ref tested (AD-32, ad-012 clause 6). The spec should cite this as its reason (see M1).
- **A separate job is a better design than A3's step inside `e2e`.** The journeys plus ZAP job takes about 5.5 minutes; the suite is several times that. Run in series, the suite would break `e2e`'s 40-minute timeout and lengthen every pull request. Run as a parallel job, it adds wall time only to the pull requests it triggers. It needs its own runner and Docker daemon, so the stacks do not collide. The cost is one extra cold image build per triggered pull request. AD-32 still has to say so (D2).
- **The suite should run on a hosted runner as-is.**
  - `docker-compose.yml:24` sets `name: disputedesk`, so the fixed container names `disputedesk-postgres-1` and `disputedesk-redpanda-1` in `run-regression.sh:35` and `support.ts:22,48` resolve.
  - Node comes from `setup-node`, and Playwright sets `forbidOnly` from `CI`.
  - `QA_DB_PASSWORD` has its dev default, so no secret is needed and a fork pull request runs the same way.
  - Each spec's environment (`E2E_LINKING_*`) is set by the script.
- **Security checklist** (CI-only change: no endpoint, session, linking, data or header change).
  - The trigger stays `pull_request`, not `pull_request_target`. Permissions stay `contents: read`, checkout keeps `persist-credentials: false`, and no secret is needed. No package is added.
  - The diagnostics print `docker compose logs` and `error-context.md` into a public log. The data is synthetic fixture data, the same exposure the `e2e` job already has. The SMS sender delivers OTPs to Mailpit over SMTP (`SmtpSmsSender`) and does not log them.
  - Only L3 applies.
