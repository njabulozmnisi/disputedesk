## Criteria through the browser and network

### 1 SPA served by the non-root gateway
- Browser: `/` renders the start page; deep links `/transactions`, `/disputes`, `/link`, `/signed-out`, `/no-such-route` each return 200 with the SPA shell (index.html fallback), and the SPA routes them as 2.4 records (transactions list for a linked customer, the not-found screen for unbuilt paths).
- Network: `GET /assets/nope.js` and `GET /assets/` return 404, with CSP, `nosniff` and `Referrer-Policy` present once. Assets load from `/assets/index-*.js`, `index-*.css` and four `nunito-sans` woff2 files, all same-origin.
- Not browser-checkable here: non-root, pinned image, build context (verifier and security covered them; security saw UID 101).

### 2 Security headers once, as the browser sees them
Document responses seen by the browser on `/`, `/transactions`, `/disputes`, `/link`, `/signed-out` and `/no-such-route` are identical to curl on `/`:

| Header | Value (once each) |
|---|---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; frame-ancestors 'none'; base-uri 'self'; form-action 'self' http://auth.localhost:8080` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `X-Frame-Options` | `DENY` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=()` |
| `Cross-Origin-Opener-Policy` | `same-origin` |
| `Strict-Transport-Security` | absent locally (as specified: AWS only) |

- `/api/health/live`: `Cache-Control: no-store, no-cache` once, the gateway headers once each, no HSTS.
- 429: 60 rapid requests to `/api/health/live` gave 25 x 200 and 35 x 429. The 429 is `Content-Type: application/problem+json`, `Retry-After: 1`, body `{"type":"https://github.com/njabulozmnisi/disputedesk/blob/main/docs/problems/rate-limited.md","title":"Too many requests","status":429}` with no `traceId` (RFC 6585, RFC 9457).

### 3 Forwarded headers and templated hosts
Browser view: the sign-in redirected `localhost:8080` to `auth.localhost:8080` and back to `/transactions`, so the templated auth host and `form-action` origin work. The single-value `X-Forwarded-For` is the supervisor's and security's check, not repeated.

### 4 Same-origin telemetry proxy
`GET /otlp/v1/traces` 405; `POST` of an empty JSON `resourceSpans` 200; a 2 MB body 413 (1 MB cap). The browser sent no OTLP request (the SPA has no exporter yet, as the challenge noted).

### 7 Radix limit
- `alert-dialog.tsx` carries the `// shortcut:` comment (builder and reviewer read it) and the CSP keeps `style-src 'self'` with no nonce or `'unsafe-inline'` (header above).
- Browser, clock-driven: no dialog at 12:50 of inactivity; dialog at 13:10 reading "You'll be signed out soon. For your security, we sign you out after 15 minutes without activity." with buttons "Stay signed in" and "Sign out". Exactly one `securitypolicyviolation` event (`style-src-elem`, blocked URI `inline`) and exactly one console error, the Radix text above. `body` carries `data-scroll-locked="1"` but the injected `<style>` is blocked, so `window.scrollBy(0, 400)` moves the page (`scrollY` 400): the recorded limit. Escape closes the dialog.

## Tracer bullet and origins
- Customer A signs in through the hosted login (Zitadel v2 login, `auth.localhost:8080`) and lands on `http://localhost:8080/transactions` with 20 rows; `GET /api/v1/transactions` same-origin. The e2e (tests 6 to 8) checks the rows against the API and the database (`qa_readonly`).
- The login page is Zitadel's default look: theming is story 2.6 (planned), not this story, so "themed" could not be checked and is not a finding.
- Origins contacted during sign-in and browsing: `http://localhost:8080` and `http://auth.localhost:8080` only. Every `fetch`/XHR the SPA made went to `localhost:8080` (`/api/v1/bff/session`, `/api/v1/transactions`); the `auth.localhost:8080` traffic is the top-level navigation to the identity provider and that page's own assets, which `connect-src 'self'` does not govern and `form-action` explicitly allows. No third-party origin and no console error during the whole walk.
- The auth host sends its own policy (`script-src 'self' 'unsafe-inline' 'unsafe-eval'`, its own HSTS); the app CSP is deliberately not applied there (challenge). Informational only.

## Findings

| Q1 | low | gateway static responses (`/`, `/assets/*`) | No `Cache-Control` header: `index.html` and the hashed assets rely on heuristic caching from `Last-Modified`.
