Security (pre-build), base `1b5fc87`, story file from the working tree. I did not read `2.6-challenge.md`. No high, no `[decision]`. Checked against `infra/zitadel/provision/provision.sh`, `verify.sh`, `docker-compose.yml`, `infra/nginx/templates/` and the Zitadel source at `v4.20.0` (the lab clone under `~/disputedesk-research/labs/zitadel-lab/theming-research/z`).

**Already covered:**
- The new calls reuse the provisioning PAT from the existing IAM_OWNER bootstrap volume. The story needs no new PAT, scope or volume mount.
- The existing `AUTH_HEADER` file (`provision.sh:34-37`, mode 077, removed on exit) keeps the PAT off the command line.
- Email verification and Mailpit SMTP are already provisioned and checked (`docker-compose.yml:169`, `verify.sh:68-70`).
- **CSP for the uploaded font and logo.** Login v2 sends `font-src 'self' <ZITADEL_API_URL>` and `img-src 'self' <ZITADEL_API_URL>` (`apps/login/src/lib/csp.ts`). The login is served on the identity origin under `/ui/v2/login`, and `/assets/v1/...` is proxied on that same origin (`nginx.conf.template`, identity server block). So the asset URLs Zitadel returns (`http://auth.localhost:8080/assets/v1/...`) are `'self'`, and no CSP change is needed. The lab confirmed the logo renders this way (zitadel_lab.md:275).
