### Fix list, item by item

1. **Window focus (security M1, verifier criterion 4): closed.** `focusManager.setEventListener` with `visibilitychange` and `focus` on `window`, the form TanStack documents in `focusManager.ts` (installed 5.105.0, whose default listens to `visibilitychange` only). The criterion-4 tests now dispatch real `visibilitychange` (bubbling from `document` to `window`) and window `focus` events; no `focusManager.setFocused` remains. Two events in one tab switch make one request: TanStack refetches on focus with `cancelRefetch: false`, and the test asserts one session request.
2. **Leave once (verifier criterion 1, reviewer 2): closed.** Module-level `leaving` guard in `leaveForSessionEnded`; the new test drives the real event pair plus a 401 and fails without the guard.
3. **QueryCache `onSuccess` (reviewer 3): closed.** The effect and ref are gone from `RootLayout`; `handleSuccess` sits beside `handleError`. Checked in installed `query-core/src/query.ts`: the cache's `onSuccess` is called right after `setData` in `fetch`, and `setQueryData` never calls it, so the comment is accurate. Three unit tests cover signed-in then anonymous (leave), anonymous first (stay), and `setQueryData` (stay). The wrong comment is removed.
4. **Sign-out failure behind the modal (reviewer 1): closed.** The failure shows inside the dialog as `role="alert"`, asserted by role without `hidden: true` and contained in the `alertdialog`. The message is one shared constant (`signOutFailedMessage`).
5. **`RaiseDraft` (reviewer 4): closed.** The `signedIn` prop, the clearing and the false comment are removed; the new comment (a session ends with a page navigation, which drops the draft) is true: no production code writes an `anonymous` session with `setQueryData`, so a signed-out render without a navigation cannot happen.
6. **Lows: all taken.** `retry: false` with a test; `useSessionTabs` returns `warningOpen`; `raiseTelemetry.test.tsx` stubs `location` and asserts one leave; `vi.unstubAllGlobals()` moved to `afterEach` in `ReviewScreen`, `TransactionsScreen` and `signOut` tests (and `raiseTelemetry`); `refetchOnWindowFocus` is the documented function form, reading the same `signedIn` the cache keeps.

### Unlisted changes, judged

- **`startNewDocument()` reset in `setup.ts`: acceptable.** jsdom's `location.replace` does not unload the document, so a module-level guard needs a per-test reset; a named reset called once from the global `afterEach` is the plainest way. It is two lines of test-only code in a production module, documented as such. No finding.
- **`RaiseDraft.test.tsx` rewrite: nothing lost beyond the signedIn clearing.** The old file held only the four clearing tests (its `setUp` asserted the draft, the submitted ID and the server errors only as preconditions). The new file adds three tests the old one never had: the draft is held for its transaction only, the Idempotency-Key is kept for an equal request and renewed for a different one, and submitted IDs are remembered per transaction.
- **`signOutFailed` alert inside the dialog: correct, one low.** The page notice behind stays (aria-hidden while the modal is open) and becomes reachable once the dialog closes, which is the existing page behaviour. See L1 for the reopened-dialog case.
- **The leaving guard stays set after a failed navigation: acceptable.** A `location.replace` to `/signed-out` that does not load (offline, a server error) still replaces the document with the browser's error page or the error response, so the heap is dropped either way; the app registers no `beforeunload`. The only document that survives is one whose navigation is aborted (a 204 or a download response), which the gateway does not serve for an SPA route. Retrying would not help that case either. No finding.

### Findings

No high or medium findings.

- **L1 (low), `frontend/src/app/InactivityWarning.tsx:74`.** `signOutFailed` comes from `useSignOut`, which resets it only on the next sign-out attempt. After a failed sign-out, a successful "Stay signed in" and 13 more idle minutes, the next warning opens with "We couldn't finish signing you out. Try again." already shown and announced, though the person did not try to sign out this time. Fix: reset `failed` when the warning closes, or show the in-dialog alert only for a sign-out pressed while this warning is open.
- **L2 (low), `frontend/src/app/sessionEnd.test.tsx:144`.** The test is named "several 401s", but `/disputes` makes one request (`useGetApiV1DisputesInfinite`, no retry on 401), so it proves one session answer plus one 401. The guard is generic and the mutation check shows the test fails without it; rename the test or fail a second request to match the fix list's wording.
- **L3 (low, simplicity), `frontend/src/api/queryClient.ts:60-62`.** `handleSuccess` ignores its `data` argument and re-reads the cache with `getQueryData`. It is correct (the cache's `onSuccess` runs after `setData`) and avoids a cast, so it stays; noted only because a reader may wonder why `data` is unused. A one-line comment would answer it.
