# 8.9 security review (Feature, security flag: the gateways' forwarded headers, 2026-11-05)

Patch `8.9.patch` on base `e0c5e53`, built on the M1, applied with `git apply --3way --binary` (clean) to a throwaway worktree at `0177b43` and removed afterwards. Change: in both gateway templates the app and identity servers each set `proxy_http_version 1.1` and the forwarded-header block once (`Connection ""`, `Host`, `X-Forwarded-Host`, `X-Forwarded-Proto`, `X-Forwarded-For $remote_addr`, `Forwarded ""`, `X-Origin-Verify ""`), and 14 per-location copies are deleted; the local block gains `X-Origin-Verify ""` (human decision 2026-11-04, `epic-8-decisions.md`); the header comments state the inheritance rule; one test change sends a client `X-Origin-Verify` on the seven local per-route rows. Pass: no high or medium findings.

## Checked

- **Only proxy directives and comments change.** Every changed template line, comments aside, is a `proxy_set_header` or `proxy_http_version`. No `add_header`, `include`, `limit_req`, `error_page`, `proxy_pass`, `proxy_hide_header`, `if`, `log_format` or `server_name` line changes; `security-headers`, `identity-headers` and `scalar-headers` templates, the Dockerfile and the AWS Mailpit server are untouched. CSP, HSTS (AWS only), X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy and COOP are therefore unchanged, and the GatewayTests that assert them (HSTS once on pages, 403 and 404; the identity baseline; the app security headers) pass. OWASP Secure Headers Project; ASVS 5.0 V3.4.
- **Inheritance holds on every proxied location.** Per nginx `proxy_set_header` ("inherited from the previous configuration level if and only if there are no proxy_set_header directives defined on the current level", <https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header>), a location loses the block only if it sets its own. In the patched templates the only locations with their own `proxy_set_header` are local `/otlp/` and the AWS Mailpit location, as before. The header files included at location level hold no `proxy_set_header` (only `add_header` and, in identity-headers, `proxy_hide_header`), so `include /etc/nginx/scalar-headers.conf` and `include /etc/nginx/identity-headers.conf` in `/scalar*`, `/openapi/v1.json` and `/ui/v2/login` do not break inheritance. The server-level `if ($http_x_origin_verify != ...) { return 403; }` in AWS still runs before any location and is unchanged.
- **Header spoofing, both gateways.** `ProxiedLocation_UpstreamRequest_HoldsExactlyTheHeadersItsLocationSets` (14 rows, both images) asserts the exact set of header names each upstream receives, with the client sending `Forwarded: for=203.0.113.9;host=evil.example;proto=http` and, locally, `X-Origin-Verify: client-sent`; `Host` and `X-Forwarded-Host` are the fixed origin name, `X-Forwarded-For` the peer (or realip's CloudFront viewer), `X-Forwarded-Proto` `$scheme` or the mapped `$forwarded_proto`. A header a location stops dropping fails the exact-names check, which is the guard against the inheritance rule (the story's Supervisor checks). `AwsGateway_ViewerAddressFromATrustedClient_...` asserts no `X-Origin-Verify` upstream with the real secret sent; `AwsGateway_ClientsOwnForwardedFor_IsDropped` and the `CloudFront-Forwarded-Proto` theory are unchanged and pass. `ProxiedLocationCases_CoverEveryProxyPassInTheTemplate` still counts every `proxy_pass`. ASVS 5.0 V4.1.3 (intermediary-set headers such as `X-Forwarded-*` cannot be overridden by the end user).
- **Origin-verify secret never logged or echoed.** No log format changes; `path_only` logs no request header. `AwsGateway_OriginVerifyValue_IsInNoLogFormatAndNoLogLine` passes. The secret still reaches no upstream on any AWS route (app and identity by the server block, Mailpit by its own unchanged set). The 403 is nginx's own body. The test change sends only a literal `client-sent`, not the fixture secret. ASVS 5.0 V16.2.5, V13.3.1 (CloudFront, "Adding custom headers to origin requests").
- **Local gateway now strips a client `X-Origin-Verify`.** Stronger than before on every local route but `/otlp/` (L1). Matches the human decision of 2026-11-04.
- **`proxy_http_version 1.1` at server level.** Applies only where `proxy_pass` runs; `Connection ""` with HTTP/1.1 is nginx's documented form for upstream keepalive (<https://nginx.org/en/docs/http/ngx_http_upstream_module.html#keepalive>, <https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_http_version>). The tests assert version `1.1` on every route.
- **Standards.** No new mechanism: nginx `proxy_set_header` inheritance and an empty value to drop a header, both from the nginx proxy module documentation; no home-grown security mechanism.
