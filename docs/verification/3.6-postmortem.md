# Postmortem: 3.6 second fix round

Trigger: a second fix round (AGENTS.md, Continuous improvement).

- What happened: round 1 item 14 removed a double group label by deleting `aria-labelledby` from the Radix `RadioGroup`, leaving `role="radiogroup"` unnamed. The builder's assumption ("the legend alone names the radio group") was wrong: a `<legend>` names the `<fieldset>`, not the inner radiogroup. Vitest passed because no test asserted the radiogroup's name.
- Stage that caught it: reviewer (delta). Stage that should have: builder self-check.
- Category: missing test (accessibility).
- Countermeasure proposed (needs approval: a new dev package): an automated accessibility check in the component tests, `vitest-axe` (axe-core) run on each raise and review screen render, so an unnamed role fails a test. Until approved, one Known pitfalls line in the build-story skill: "every ARIA role that requires a name is asserted by name with `getByRole(role, { name })`".
