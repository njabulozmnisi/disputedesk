# 7.14 pre-build security

Security agent (read-only, main at commit "docs: e2e tooling batch merge check, escapes and metrics" (2026-10-31)), 2026-10-31. Verdict: findings, all `[story]`.

1. [story] medium. A session answered as 200 `anonymous` is never cleared (`InactivityWarning.tsx:69-78`) and counts as activity (`:46-47`). One clean-up function runs on every change to `anonymous` (401, a session answer of `anonymous`, the idle limit, sign-out, either broadcast message, a bfcache restore) and posts `expired`; an `anonymous` session response is not activity; add a test.
2. [story] medium. Mutations are not cancelled; their success handlers write customer data back (`WithdrawDialog.tsx:165`, `ReviewScreen.tsx:105-107`). Clear the mutation cache and make post-session success writes do nothing; test sign-out with a withdraw in flight.
3. [story] medium. A 15-minute `setTimeout` drifts across OS sleep and background throttling. Store the deadline (last activity plus 15 minutes) and check it on `visibilitychange`, `focus` and `pageshow` as well as the timer; test by advancing the clock without firing the timeout.
4. [story] low. bfcache: `location.reload()` on `pageshow` with `persisted` (web.dev) is simpler and leaves nothing in memory; prefer it or state the accepted frame.
5. [story] low. Post `signed-out` only after the token fetch succeeds, immediately before `form.submit()` (supervisor ruling in `7.14-prebuild-review.md`).
6. [story] low. `7.14-run.md` keeps keys, offsets, versions and counts only, never event payloads.
