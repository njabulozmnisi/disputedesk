# 8.4 security review (High-stakes for one production change, 2026-11-04)

Production change: `CoreBankingRegistration.cs` calls `IHttpClientBuilder.RemoveAllLoggers()` on the `ICoreBankingClient` and `ISimSwapCheck` clients (Microsoft Learn, `HttpClientBuilderExtensions.RemoveAllLoggers`). Pass: no high or medium findings.

- The two factory clients are the only `AddHttpClient` registrations in `src/`; SMS uses SMTP. A probe against Microsoft.Extensions.Diagnostics.Testing 10.11.0 at Trace showed the default logger's "Start processing" and "Sending" records carry `X-Customer-Id=["…"]` in structured state while the message is redacted; with `RemoveAllLoggers` there are no HttpClient records. OpenTelemetry HttpClient instrumentation records no request headers by default. ASVS 5.0 V16.2.5, V14.2.
- Test-only part weakens no privacy assertion (FakeLogCollector keeps message plus every structured value; MetricCollector keeps every exact tag-set check).
- Supervisor reproduced the break on the real tests: without `RemoveAllLoggers` on `ICoreBankingClient`, `CoreBankingClientTests` fails 2 of 17 (the two customer-ID tests); restored.
- `scripts/secret-scan.sh`: no leaks. No vulnerable packages.
