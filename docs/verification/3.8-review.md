## Postmortem: fix round could not reach the story worktree (trigger: stage failing for tooling)

- **What happened.** The fix round was dispatched as a fresh `backend-builder`, whose definition sets `isolation: worktree`. The harness gave it a new worktree from main and confined its writes there, so it could not change the story worktree; the guard hook also refused a patch outside `backend/`. It made no changes and returned `blocked` with a plan. Its empty worktree was removed automatically, so it could not be resumed. Cost: one builder run (about 5 minutes, 140k tokens).
- **Category.** Environment or tooling.
- **Root cause.** CLAUDE.md asks for one fresh builder per fix round, but a fresh isolated builder always starts from main, never from the story's uncommitted change.
- **Workaround used.** The supervisor exported the story worktree's whole uncommitted change against the base (a temporary git index, `git diff --cached --binary`), checked it reproduces the worktree in a throwaway worktree, and the fresh builder applied it in its own worktree first.
- **Proposed countermeasure (needs the human, as a rule change).** A deterministic step: `scripts/story-patch.sh <worktree> <base>` writes the patch and exits non-zero unless applying it to the base reproduces the worktree; the fix-round dispatch brief always starts with applying it. Alternative: the story branch gets a work-in-progress commit before a fix round, which needs a commit approval each time.

- **Decision (human, 2026-10-29): approved.** `scripts/story-patch.sh` is written and tested against the 3.8 worktree (54 files, byte-identical to the hand-made patch, story index untouched); `docs/process/agentic-sdlc.md` states the fix-round dispatch step.
