  `docker compose exec -T postgres`) instead of an interactive session: the same role and the same SQL text. `rpk` was
  given no standard input (`</dev/null`).

## Result

Every command exited 0 and every documented outcome held: raising answered 201 and readiness stayed healthy during
the outage, the backlog was `Pending` with 0 attempts, the Worker logged both warnings, and after
`docker compose start redpanda` the count was back to the baseline within 10 s with each dispute's events in
`disputeVersion` order. The procedure needed no change after the run.

Not checked in this run: the failed `send disputedesk.disputes` spans in the Aspire Dashboard (a browser view, not a
command). No `Pending` row with 1 to 4 attempts or `Failed` row arose, as expected for an outage, so step 2's reading of
those rows was not exercised here (procedure 1's drill in `7.7-run.md` exercises `Failed`).
