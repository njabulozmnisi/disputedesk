# 7.3 pre-build security (status: findings)

What already holds:
- `packages: write` is only on `publish`.
- The registry login takes `GITHUB_TOKEN` through stdin.
- There is no `latest` tag and no third-party action.
- The ZAP image is pinned by digest, and any untriaged alert fails the job.
- Checkout uses `persist-credentials: false`.

- **S7.3-1 medium [story] An image can be published before Trivy has passed on that commit, and Trivy scans a different build.**
  - Problem: `publish` needs only CI jobs. `security.yml` is a separate workflow that runs at the same time on a push to main. Commits reach main by direct push (`scripts/push-and-watch.sh`), so the pull-request Trivy run of criterion 6 usually never happens before a publish. `security.yml` also scans its own build (`docker build -t disputedesk-api:ci backend` uses the default target, not explicitly `api`), not the bytes that get pushed.
  - Fix:
    - In `publish`, install Trivy with the same version and SHA-256 pin as `security.yml`.
    - Run `trivy image --scanners vuln,secret --severity HIGH,CRITICAL --exit-code 1` on each built image before its `docker push`, so a failure pushes nothing. The secret scanner is there because 7.5 assumes the packages are public.
    - In `security.yml`, add `--target api` so the scanned target is the published one.
  - Standard: ASVS 5.0 V15.2 (no components with known vulnerabilities); Trivy image docs.
  - Builder must test: `actionlint` passes; each image's scan step comes before its push step. Supervisor: on a throwaway branch, a failing scan stops the job before any push.

- **S7.3-2 low [story] Images carry no link to their source.**
  - Fix: build each image with `--label org.opencontainers.image.source=https://github.com/$GITHUB_REPOSITORY` and `--label org.opencontainers.image.revision=$GITHUB_SHA`. This links each package to the repo and lets 7.5 check that a digest's revision is the requested SHA.
  - SLSA build attestations would need a new action, so they go in `docs/production-path.md`.
  - Standard: OCI image-spec annotations; GitHub, *Connecting a repository to a package*.
  - Builder must test: the job summary prints each image's revision label next to its digest.

- **S7.3-3 low [story] Workflow hygiene.**
  - Fix:
    - No `${{ github.* }}` expression inside any `run:` script. Pass values through `env:` (GitHub, *Security hardening for GitHub Actions*, script injection).
    - No `set -x` in `publish`.
    - Run `docker logout ghcr.io` in an `if: always()` step.
    - `e2e` stays on `pull_request`, never `pull_request_target`.
  - The repo looks public, so CI logs are public. The failure step's `docker compose logs --tail 200` is acceptable only because every local value is dev-only and synthetic. Do not add `docker compose config` or any print of the environment.
  - Builder must test: `actionlint` passes, and the reviewer reads every `run:` block.

## Resolution

Sofia, 2026-10-30. Every point was `[story]`; all are folded into the story, still 6 criteria.

- S7.3-1: `publish` installs Trivy with the same pin and scans each built image (`vuln,secret`) before its push; `security.yml` names `--target api`; a supervisor check proves a failing scan pushes nothing (criteria 5 and 6).
- S7.3-2: OCI `source` and `revision` labels; the summary prints the revision beside each digest (criterion 5); SLSA attestations go to the production path through story 7.6's Notes.
- S7.3-3: no `${{ github.* }}` in `run:`, no `set -x`, `docker logout` always, `pull_request` only, no print of the Compose config or environment (criterion 4).
