## Pre-mortem
- [decision] Local startup fails: AD-23 requires the Api to resolve `gateway` at startup, but Compose starts `gateway` only after `api` has started. The trust configuration needs a bootstrap-safe address source or an explicitly designed startup sequence.
- [decision] The limits allow more requests than “in any 15 minutes” permits. The documented sliding-window limiter recycles permits by segment; FR-8 reads as a strict rolling-window guarantee.
- [story] Rejection audits name the wrong partition—or duplicate entries—because the chained limiter’s `OnRejected` lease does not identify which member rejected the request.

## Simplest design
- [story] Put `UseForwardedHeaders` before authentication and rate limiting; trust only the gateway, then chain an IP limiter and a login limiter for the two linking routes. Set zero queue, write the 429 ProblemDetails and lease-derived `Retry-After` in `OnRejected`, and use the existing audit path. Do not add a custom header parser, limiter wrapper, or separate rate-limit store.

## Assumptions
- [story] The gateway is the Api’s only trusted forwarding hop: nginx currently replaces, rather than appends to, `X-Forwarded-For`. Verify this remains true in the AWS route.
- [story] “Public app host” means the forwarded-host allowlist **without a port**. Microsoft’s `ForwardedHeadersOptions.AllowedHosts` excludes ports, while local nginx forwards `localhost:8080`; distinguish it from the currently wildcard `appsettings.json` `AllowedHosts`.
- [story] Existing TestServer requests represent a non-gateway peer. Tests must set the connection address explicitly to prove both trusted and untrusted cases, including IPv4-mapped IPv6 addresses.

## Standards
- [story] Use [ASP.NET Core’s rate-limiting middleware](https://learn.microsoft.com/en-us/aspnet/core/performance/rate-limit?view=aspnetcore-10.0) for chaining, rejection and lease metadata, and [Forwarded Headers Middleware](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer?view=aspnetcore-10.0) for proxy trust. Neither supplies a documented “rejecting partition” identifier for a chained lease; inventing lease metadata to supply one would need a justification. First-rejection audit deduplication is application-specific, not a framework mechanism.

## Gaps
- [decision] Reconcile FR-8’s “rejected requests do not count” with AD-12’s explicit exception: an IP permit is consumed when the subsequent login limiter rejects. Specify which guarantee wins and test that case.
- [story] Define the sliding-window segment count and boundary tests, whether an absent login `sub` fails closed, and which audit partition is recorded when both limits are exhausted. Criterion 2 also omits FR-10’s measurable requirement that later rejections are counted as a metric.
- [story] Promote the identity-origin logging note to a criterion and include `infra/nginx/templates/nginx.conf.template` in Touches. A live end-session request must prove its `id_token_hint` is absent from the access-log record; a config-only assertion does not prove that outcome.
