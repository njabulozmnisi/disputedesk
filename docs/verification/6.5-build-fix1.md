**What changed per item:**
1. **Budget bounds.** `Linking:Budget` must now be from 1 to 60 seconds. I added a 999 ms case; the 1 s and 60 s cases were already in `ApiStart_AtTheBounds_StartsWithThoseValues`. The error message is now "Linking:Budget must be from 1 to 60 seconds."
   - Three tests started the Api with 500 ms and now use 1 s: 6.5's `LinkingSendCapTests` lock-wait test, and 6.1's `LinkingAuditTests` budget case and `LinkingOtpSendTests.Job_SendLongerThanTheBudget…`.
   - In `Job_SendLongerThanTheBudget…` the held send now waits 2 s instead of 1 s, so it still outlasts the budget by the same ratio.
2. **Two-key lock probes.** The probes in `LinkingDatabase.cs` now count only `classid = 6005 AND objsubid = 2`.
   - The while-sending test had to change to prove the lock's form. Against a one-key lock it would still have passed, since nothing is held during the send. It now also holds the SIM-swap check and asserts exactly 1 two-key lock is held there, then asserts none while sending.
   - Its new name is `Job_HoldsTheTwoKeyCustomerLockAtTheSimSwapCheckAndNoLockAndNoOpenTransactionWhileSending` (it was `Job_WhileSending_HoldsNoAdvisoryLockAndNoOpenTransaction`, which `6.5-verify.md` and `6.5-review.md` still cite).
3. **Bounds in one place.** `MinimumQueueCapacity`, `MaximumQueueCapacity`, `MinimumBudget` and `MaximumBudget` now sit together above the properties in `LinkingOptions`. `Validate` uses them in both the checks and the interpolated messages. The tests keep the literal expected text, so any drift fails a test.
4. **`OtpSentAtUtc` doc.** It now says the value is the instant the claiming job started: the job reads the clock once (AD-4) and claims at most one `Linking:Budget` later, so the hourly window can be short by up to one budget. Doc only.
5. **Nits:**
   - `RecordAsync`'s `into` parameter is now `context`.
   - `ClientAddressStartupFilter` has a settable `Address`, and `ChangeableClientAddressStartupFilter.cs` is deleted.
   - `ThrowNext` is now the set-only method `ThrowOnNextCall(Exception)`.
   - The helper is back to its 6.1 name, `WaitIfHeldAsync`, so 6.2's fakes build unchanged.
