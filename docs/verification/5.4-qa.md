## Findings

- **F1 (test budget, needs a story or fix round, not a product defect):** all 7 of A's seeded disputes sit among A's newest 20 transactions, so page 1 (the default page size, which the SPA and several specs read) loses 7 disputable rows. `dispute-raise.spec.ts:866` and `dispute-stored-events.spec.ts:345` pick a row from page 1 and fail even on a fresh database after only the preceding tests of `dispute-raise`. The story (Boundaries) predicted 13 disputable rows remain overall; the page-1 effect is what bites. The main checkout's uncommitted data-budget edits to those specs are the intended remedy (not used here, as instructed).
- **F2 (flaky, pre-existing):** `linking-start.spec.ts:338` can fail by chance when an OTP's six digits appear inside a hex `TraceId`. Suggest matching OTPs with word boundaries or only in text columns.
- **F3 (observation):** `disputedesk.disputes.raised` showed a value of 1 (reason `unrecognised`) on the Aspire metrics page twice, at startup, on both fresh stacks, before any e2e or API call. Not seeding: the gateway log has no request, the database held exactly the 8 seeded disputes, the seeder never calls `RaiseMetrics`, and the table timestamp equals the moment the page was loaded (14:21:54, 14:22:22 on reloads) rather than a measurement time, which points at the dashboard's rendering of an instrument with no data. Not proven from the dashboard alone; the instruments that matter to criterion 5 (`dispute_actions`, `disputes.resolved`) are absent.
- **N1 (info):** the seeded stored events and outbox rows carry no trace ID or `traceparent`; the relay adds its own `traceparent` on publish. The story is silent; stated for completeness.
- **N2 (info):** the Worker log shows `libgssapi_krb5.so.2: cannot open shared object file` during the full run (a Kafka client library warning, pre-existing, not 5.4).
