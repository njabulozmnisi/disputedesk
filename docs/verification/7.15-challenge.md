## Pre-mortem
- [story] CI passes, but the eventual deploy cannot assume the role: the new job compares a token with a Terraform plan built from the *same current GitHub context*. It cannot verify the IDs and repository name previously supplied to a real Terraform apply. The README says no AWS account exists yet, so call this a subject-format check, not an end-to-end deployment proof.
- [story] A later change adds an environment or customizes the subject for `deploy.yml`. The CI job’s own token still matches its plan while the deploy job’s subject differs. GitHub documents that environments change the [subject claim](https://docs.github.com/en/actions/reference/security/oidc#example-subject-claims).

## Simplest design
- [story] Build one subject in the deploy-role module from the repository and two IDs; assert the exact policy in the existing mocked test. Add one main-only CI job that masks its token, checks `aud`, and compares `sub` with that module’s planned policy. Keep the two README exports. No second subject formatter or AWS probe is needed.

## Assumptions
- [story] The job’s subject represents the deploy job’s subject. Evidence: both are intended to run on `main` without an environment; the proposed check does not request a token from `deploy.yml`.
- [story] “1 to 19 digits” fits a signed 64-bit integer. This is false: `9999999999999999999` matches the specified regex but exceeds `9223372036854775807`. Either remove that rationale or specify and test the actual upper bound.

## Standards
- [story] No invented mechanism is necessary. Exact `aud`/`sub` trust conditions and GitHub’s [documented OIDC subject formats](https://docs.github.com/en/actions/reference/security/oidc) fit this design. Decoding the directly requested token for a CI comparison is not signature verification; the story correctly leaves credential verification to AWS STS.

## Gaps

State precisely what the offline check proves and make the first-run log inspection a post-merge check, not a pre-build acceptance test.
- [story] The CLI steps specify `-chdir` for `init` but not explicitly for the subsequent `terraform test`. Require both to run in `infra/terraform/envs/dev`; otherwise `tests-oidc` may be resolved from the repository root.
