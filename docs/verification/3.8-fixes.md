# 3.8 fixes (round 3: verifier fail on criteria 5 and 12; human decision 2026-10-29)

Base: round-2 worktree `agent-ab85795e1e426353c`, carried as `3.8-round2.patch` (verified by `scripts/story-patch.sh`, 58 files).

1. **One instant, at the stored precision.** The raise handler reads the clock once (AD-4) and truncates that instant to whole microseconds there, before it reaches the aggregate, so the `Disputes` row, the stored event, the outbox row, the 201 body and the CloudEvent `time` all hold the same value. PostgreSQL `timestamptz` keeps microseconds (PostgreSQL docs, *Date/Time Types*); .NET `DateTimeOffset` keeps 100 ns ticks. Use the plainest documented expression (e.g. subtracting `Ticks % TimeSpan.TicksPerMicrosecond`), no helper type.
2. **Tests prove exact equality.** Remove the microsecond truncation from `DisputeCommitTests.cs` (around line 87) and `StoredEventReplayTests.cs` (around line 142), and from any other assertion that truncates to hide it; the fixed clock in those tests uses a value that is not microsecond-aligned (e.g. ending `.1234567`), and the assertions compare without truncation. A deliberate break (removing the truncation in the handler) must fail them.
